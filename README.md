# 小忆 RAG 知识库问答

一个面向**长篇资料问答**的 RAG 系统：把 Markdown/文本资料切分入库，支持多轮追问、引用溯源与效果反馈闭环。

核心不是"能回答问题"，而是**能证明答得准**：每一句回答都带可点击的引用角标，落到原文的具体段落；检索效果有可复现的量化指标（见下方数据）。

---

## 一、效果数据

在 11 道人工标注题（覆盖活动规则、借阅规则、空间预约、期刊借阅等 6 份资料）上的实测结果：

| 检索档位 | Recall@1 | Recall@3 | Recall@5 | MRR |
|---|---|---|---|---|
| 纯向量（dense） | 0.455 | 0.909 | 0.909 | 0.649 |
| 纯稀疏 BM25 | 0.636 | 0.818 | 1.000 | 0.758 |
| **双路 RRF 融合** | **0.727** | **1.000** | **1.000** | **0.833** |
| 融合 + 精排 | 0.727 | 1.000 | 1.000 | 0.833 |

**混合检索相比纯向量：Recall@1 提升 60%，MRR 提升 28%，Recall@3 达 100%（零漏检）。**

> 复现：`python tests/eval/retrieval_metrics.py --modes all`
> 完整报告：[docs/04-评测/检索效果评测报告.md](docs/04-评测/检索效果评测报告.md)

### 一个诚实的说明

「hybrid」与「rrf」指标完全相同，原因是**本项目当前没有启用真精排**：
未配置 `RERANK_ENDPOINT` 时走的是 `LexicalReranker`（严格保序，只用词项分作解释字段），
输出顺序与纯 RRF 一致，指标必然相同。

这点已被代码审查确认并修正了标注（原实现误标 `score_stage=rerank`）。
精排接口是**可插拔的**，接了外部 rerank 服务或本地 cross-encoder 即可生效，
届时需重跑评测验证增益。

详见 [RAG 核心实现审查报告](docs/04-评测/RAG核心实现审查报告.md)。

### 为什么是双后端

不是堆技术栈，是**职责边界**：

| 层 | 管什么 | 为什么放这 |
|---|---|---|
| Java | 事务、权限、持久化、任务状态机 | 这些要"稳"，JPA + Flyway 能保证 schema 可回溯 |
| Python | 检索算法、模型调用、流式生成 | 这些要"变"，换 embedding 模型、调 RRF 参数不用碰 Java |

代价也真实存在：两套依赖、跨语言契约校验、`INTERNAL_TOKEN` 双端一致、索引任务的跨进程轮询。这些复杂度在 `backend/java-api` 的 `IndexTaskPoller` 和 `AiServiceClient` 里能直接看到。

## 三、RAG 链路

```
用户提问
  │
  ├─ 查询改写：多轮场景下做指代消解（"它"→"讨论空间"）
  │            失败自动降级为原问题，不阻断链路
  │
  ├─ 双路召回
  │    ├─ 向量：Milvus COSINE 相似度
  │    └─ 稀疏：BM25（jieba 分词，数学自实现）
  │
  ├─ RRF 融合：只用名次不用分数，免疫两路分数量纲差异
  │            k=60，ties 按 chunk_id 字典序保证结果确定
  │
  ├─ 精排：对融合候选重排序（可开关，用于效果对比实验）
  │
  └─ 生成：带引用的结构化回答，SSE 流式返回
```

**关键设计取舍**：RRF 而非加权求和。BM25 分数无上界（0~20+），余弦相似度在 0~1，加权需归一化且对分布敏感；RRF 只用名次，天然免疫量纲问题。

## 四、工程实现

| 能力 | 实现 |
|---|---|
| 流式响应 | `SseEmitter` 手写帧转发，逐帧 flush 不攒批；`AsyncConfig` 自定义线程池避免阻塞 Tomcat |
| 数据隔离 | 每次检索强制 `user_id` 过滤，索引按 `(user_id, task_id)` 分区 |
| Schema 演进 | Flyway 11 个版本化迁移，禁止手工改表 |
| 索引一致性 | 写入不 flush，检索用 `consistency_level=Strong` 保证"刚建完库立刻能搜到" |
| 降级策略 | 改写失败用原问题；重排失败用融合顺序；向量库不可用回落 SQLite 切片；均有明确日志 |
| 契约保护 | OpenAPI 双份（公开/内部）+ 契约漂移检查 + 前端类型自动生成 |
| 中文处理 | jieba 分词自管，BM25 数学与 RRF 在项目内实现，不依赖检索框架 |

## 六、快速开始

### 前置

JDK 21 · Maven 3.9 · Node 18+ · Python 3.12 · MySQL 8

### 启动

```powershell
# 1. 构建（首次或改动后）
cd backend/java-api && mvn -DskipTests package
cd ../../apps/web && npm install && npm run build:only

# 2. 启动后端（Python AI 8000 + Java 8080）
deploy\start-backend.bat

# 3. 启动前端（nginx 8088）
deploy\start-frontend.bat
```

打开 `http://127.0.0.1:8088`

| 账号 | 密码 | 角色 |
|---|---|---|
| `admin` | `Admin@123456` | 管理员（用户管理 / 审计日志） |
| `user` | `User@12345678` | 普通用户（对话 / 知识库 / 评测） |

详细步骤与排错见 [docs/00-本地启动手册.md](docs/00-本地启动手册.md)。

> 向量库默认用 **milvus-lite**（纯 Python 内嵌，无需 Docker）。想用独立 Milvus 服务，改 `scripts/make_launchers.py` 里的 `XIAOYI_MILVUS_URI` 为 `MILVUS_URI=http://127.0.0.1:19530` 即可。

## 八、已知边界

诚实列出，避免过度承诺：

1. **评测样本量小**（11 题）。数字有参考价值，但不宣称统计显著性。
2. **ground truth 是文件级**，衡量"能否找到正确文档"，非"能否定位到正确段落"。
3. **未启用真精排**：`RERANK_ENDPOINT` 未配置，当前走保序降级路径；接口可插拔，接入后需重跑评测。
4. **单机部署**，无分布式；SSE 长连接未做多实例负载均衡。
5. **文档解析限 Markdown/纯文本**，不支持 PDF/扫描件 OCR。
6. **查询改写依赖 LLM 调用**，会引入一次额外延迟（失败时降级，不阻断）。
