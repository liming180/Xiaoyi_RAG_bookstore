# F3 状态提示

> 示意图定义：资料或参数变化后，提醒重新建库。
> 指导书：资料或分块设置改变后，提示"需要重新建库"。对应任务1验收标准第 2、3 项。

## 原理（一句话）

**manifest 对比**：建库时把"当时的资料清单(SHA256) + 分块参数 + 嵌入模型"存为 manifest；之后每次提问前重算当前期望 manifest，两者不相等 ⇒ 旧库失效 ⇒ 提示重建。

## 前端（界面层）

- 顶部状态徽章两态：
  - 绿色"知识库已就绪"（manifest 一致且 index.json 存在）；
  - 琥珀色"资料待更新"，并显示横幅："资料或分块设置已改变，重新建库后即可使用最新资料提问"，附"重新建库"按钮；
- 触发刷新的时机：上传/删除资料、修改分块参数、切换嵌入模型、程序启动时；
- 拦截行为：待重建状态下**阻止提问**（或点击提问时先弹重建提示）。

## 后端（逻辑层）

骨架 `read_index(cfg, data_dir, index_file)` 已实现完整校验，提问前必须先经过它：

```python
index["manifest"] != manifest_for(cfg, sources)
    → ModelError("资料、分块或嵌入模型已改变，请执行/index重新建库。")
```

逐层校验（骨架代码，可直接复用）：
1. index.json 存在且格式正确，否则"请执行/index"；
2. manifest 完全相等（模型、接口、chunk_size、chunk_overlap、每份资料的 sha256）；
3. 片段数量与当前资料重切结果一致；
4. 每个片段的 source/start/end/text 与原文重切结果一致（防止资料被改过但 SHA 恰好未更新等边缘情况）；
5. 向量维度统一且有效。

自建实现的最简版本：只做第 1、2 步即可满足验收标准。

## 前后端接口约定（网页版参考）

```
GET /api/index/status → { ready: bool, stale: bool, docs: 6, chunks: 15,
                          manifest: {...} }
```
前端据 `stale` 切换徽章与横幅。

## 验收标准（表3）

| # | 操作 | 预期 |
|---|---|---|
| 2 | 片段长度改为 120 | 界面提示需要重新建库；重建后片段数量增加 |
| 3 | 关闭程序后重新打开 | 无需重新建库即可直接提问 |
