# F10 清空对话（拓展A，+5分）

> 示意图定义：删除当前对话，开始新一轮提问。
> 指导书：点击"清空对话"后，对话记录清空，**之后的提问不再把旧对话发给模型**。

## 前端（界面层）

- 输入区旁"清空对话"按钮；
- 点击后立即清空消息列表、来源面板、检索过程表（可选确认步骤，示意网页为直接清空）；
- 清空是**纯前端 + 状态复位**操作：不清日志、不清 index.json（骨架：`/new` 时"旧日志保留"）。

**命令行版对应**：`/new` —— "已清空请求上下文，旧日志保留。"

## 后端（逻辑层）

骨架一行搞定：

```python
def new_session():
    return [], {}, uuid4().hex[:12]   # history、last、session_id 全部复位
```

- `history = []` ⇒ 下一轮 `build_rag_messages` 拼出的 messages 只有 system + 本轮 user；
- 换新 `session_id`，日志中可区分会话边界；
- `mode`、`k` **保持不变**（骨架行为；示意图 `/new` 也不重置参数）。

## 验收方法（指导书原文）

1. 输入："本次会话的代号是青禾" → 助手正常回应；
2. 清空对话；
3. 问："我刚才告诉你的代号是什么？" → **助手应无法回答**（说明旧对话确实没发给模型）。

**截图要求**：清空对话后的界面 + 验证提问的回答。

**易错点**：如果把完整 history 存在模型侧服务端（非本实验情形）或清空后仍把旧消息拼进 messages，验收就会失败 —— 用 `/show` 检查清空后首轮 messages 中除 system 外应只有本轮 user。
