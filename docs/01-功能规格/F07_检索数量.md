# F7 检索数量 k

> 示意图定义：调整每次取回的片段数量 k。
> 指导书：k 可在 1～5 之间调整，默认值为 3。

## 前端（界面层）

- 下拉框/数字输入：k ∈ {1,2,3,4,5}，默认 3；
- 位置放在输入框旁（示意图：`取回 [3] 段`），悬停提示："每次取回的资料片段数量；设为 1 可观察跨文档题的变化"；
- 修改后**开始新会话**（骨架 `/k` 行为），并与 F8/F9 页面的 k 保持同步（示意图对照测试页有独立 `evalK`，也可各自独立，报告中说明即可）；
- 范围外输入（如 0、6）前端拒绝，后端骨架同样校验 `1 ≤ k ≤ 10`。

**命令行版对应**：`/k 1`、`/k 3`。

## 后端（逻辑层）

### 学生任务一：`select_top_k(chunks, query_vector, k)` —— 骨架留空，必做

```python
def select_top_k(chunks, query_vector, k):
    scored = [dict(c, score=cosine(query_vector, c["embedding"])) for c in chunks]
    # ↓ 补全：按 score 从大到小排序，再取前 k 条
    scored.sort(key=lambda c: c["score"], reverse=True)
    return scored[:k]
```

**陷阱提醒**（最容易被扣分的地方）：
- `sort(reverse=True)` 而不是 `sort()` 后切片 `[:k]`（升序取的是最不相关的 k 条）；
- 若担心稳定性，可加次级键：`key=lambda c: (c["score"], c["chunk_id"])`；
- **不要修改原 chunks 列表的顺序**——F8 需要展示"全部片段的原始排名"，排序应在 `scored` 副本上做。

### k 对回答质量的影响（指导书图7/图8，报告思考题2）

- 跨文档题 T07（活动几点结束 + 最多借几本）：k=1 时只取回单份资料，回答不完整并说明缺哪部分；k=3 时取回两份资料，答全"16:00 结束、最多 4 本"；
- k 并非越大越好：k 过大会引入无关片段，挤占上下文、稀释注意力，甚至引入干扰资料（04/06）的噪声。
