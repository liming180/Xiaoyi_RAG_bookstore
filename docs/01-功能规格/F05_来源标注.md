# F5 来源标注

> 示意图定义：可点击编号，核对片段、得分和原文依据。
> 指导书：回答中带来源编号（如[1]）；同时列出取回的片段（片段编号、所属资料、相似度得分、片段原文）；点击编号能定位到对应片段。

## 前端（界面层）

- **来源面板**（示意图为右侧"参考来源"栏）：每条来源一张卡片，包含：
  - 引用编号 `[1]`（与回答中编号一一对应）+ 片段 ID（等宽字体）+ 所属文件名；
  - **得分条**：用横条可视化相似度得分（0–1），旁注数值；
  - **摘录**：片段正文（命中部分可 `<mark>` 高亮）；
  - `<details>` 展开完整片段原文。
- **点击联动**：点击回答中的 `[n]`，滚动定位并高亮第 n 张来源卡（示意图用 `.selected` 边框）；
- 面板底部提示语："引用只表示取回来源，仍需核对原文"（诚实呈现，加分项）。

**命令行版对应**：回答后打印"本轮来源：D01-C001 01_活动说明.md、…"；`/search 完整问题` 直接打印全部命中片段的 chunk_id/source/score/text。

## 后端（逻辑层）

- 检索结果 `hits`（来自 `select_top_k`）已含全部字段：`chunk_id, source, start, end, text, score`；
- 前端展示前**剥离 embedding 字段**（骨架 `public_hits()`），既减小传输体积也避免把向量暴露给界面；
- **编号映射**：`hits` 数组顺序即 `[1][2][3]`；回答中的编号由模型按提示词生成，若出现提示词中不存在的编号（幻觉引用），后端可做一次正则校验 `\[d+\]` 并剔除/重写（详见 PROMPTS 的 Prompt-3）；
- 命令行版直接 `json.dumps(public_hits(hits), ensure_ascii=False, indent=2)` 即可。

## 数据契约

```jsonc
citations: [
  { "ref": 1, "chunk_id": "D02-C001", "source": "02_借阅规则.md",
    "score": 0.83, "start": 0, "end": 180, "text": "……" }
]
```

## 验收标准（表4 第 2 项）

按编号查看对应片段 → 原文中确有"4本"和"21天"。

**截图要求**：两次回答（T03、T10）及对应的来源片段。

**调试技巧**：T03 答错或没标编号时，先 `/show` 看发给模型的 messages —— 确认片段编号在、提示词约束在；再看 `/search 普通图书最多同时借阅几本借多久` 的得分排名，确认 D02 片段确实排进了前 k。
