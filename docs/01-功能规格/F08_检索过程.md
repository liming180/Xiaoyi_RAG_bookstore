# F8 检索过程

> 示意图定义：展示片段排名、匹配得分和取回界线。
> 指导书：可查看某次提问时**全部片段**的得分排名，并标出被取回的前 k 个片段。

## 前端（界面层）

- 独立"检索过程"Tab，展示**最近一次提问**的检索明细；
- 表格列：**排名、片段ID、所属资料、得分、片段摘录**；
- **取回界线的两种视觉表达**（示意图做法，二选一或都用）：
  - 前 k 行浅色底纹标记"取回"；
  - 第 k 行下方虚线分隔（`.cut`），之下为"未取回"；
- 表格上方显示当前问题与参数（k、片段长度、重叠）；
- 全部片段按 **score 从高到低**排列；数据量小（~15 行）无需分页。

**命令行版对应**：`/search 完整问题` 打印全部片段得分排名（骨架实现为只打印前 k；可自行扩展打印全部并标注 `取回/未取回`，更贴合验收）。

## 后端（逻辑层）

**核心原则：trace 保留全量排序结果，k 只是截取线。**

```python
# 推荐实现：select_top_k 之外另给一个全量函数，或让其返回 (hits, trace)
def rank_all(chunks, query_vector):
    scored = [dict(c, score=cosine(query_vector, c["embedding"])) for c in chunks]
    scored.sort(key=lambda c: c["score"], reverse=True)
    for i, c in enumerate(scored, 1):
        c["rank"] = i
    return scored          # trace：全部片段带排名

hits = trace[:k]           # 取回的前 k 个
for c in trace:
    c["retrieved"] = c["rank"] <= k
```

- 日志中 `retrieved` 字段建议存**全量 trace**（骨架存的是前 k 的 public_hits，可扩展），便于报告截图与调试；
- 与 F5 的区分：F5 只展示**被取回**的片段（来源卡片）；F8 展示**全部**片段的排名与界线；
- 相似度得分为余弦值（-1~1，实际多在 0.3~0.8），展示时保留 2~3 位小数即可。

## 调试价值（附录B：跨文档题答不全、检索结果不对时）

1. 打开检索过程看排名：目标片段（如 D01 的"16:00"片段、D02 的"4本"片段）是否排进了前 k？
2. 排名太低 → 调小片段长度（180→120，让关键句不被长片段稀释）或调大 k；
3. 干扰资料（04期刊规则/06留言）挤进前 k → 检查问题措辞与提示词约束，属正常现象，报告中分析即可。

## 验收标准（表6 第 3 项）

打开检索过程 → 全部片段按得分从高到低排列，能看出前 k 个片段。
