# F1 资料管理

> 示意图定义：列出、查看、上传与删除 .md / .txt 资料。
> 对应任务1（20分）验收标准第 1 项。

## 前端（界面层）

**展示**
- 侧边栏"我的知识库"文件列表：每行显示 **文件名 + 字数**（示意图还显示片段数）；
- 未核实资料（`06_成员留言摘录.md`）显示琥珀色"未核实"标记（配合 F11）；
- 顶部计数徽章（如"6 份资料"）。

**交互**
- **添加**：上传按钮 + 拖拽区，仅接受 `.md` / `.txt`，单份 ≤ 2MB；空文件、格式不符的文件静默跳过并提示；
- **删除**：每行悬浮出现删除按钮，删除后立即触发 F3"待重建"状态；
- **查看**：点击文件名弹出全文弹窗（拓展B可升级为片段视图）。

**命令行版对应**：`data` 文件夹即"列表"；添加/删除=向 `data` 放入/移出文件；查看=`/search` 结果或直接打开文件。

## 后端（逻辑层）

参考骨架 `rag_core.load_chunks(data_dir, size, overlap)`，要点：

1. 只读 `data/` 下扩展名为 `.txt` / `.md` 的文件，按文件名排序，`enumerate(files, 1)` 得到文档号 `D01、D02…`；
2. 用 `encoding="utf-8-sig"` 读取（同时兼容带/不带 BOM）；
3. **空正文拒绝**：`text.strip()` 为空时报错"没有正文"，不要让空文件进索引；
4. 每份资料登记 `{"source": 文件名, "sha256": sha256(正文)}` —— SHA256 是 F3 判断"资料是否变化"的依据；
5. 字数统计直接 `len(text)`，前端展示用，不进索引。

**安全提示（对照指导书）**：`questions.csv` 绝不能放进 `data/`，否则会被当资料切片建库。

## 前后端接口约定（网页版参考）

```
GET    /api/docs            → [{name, chars, verified}]
POST   /api/docs/upload     (multipart) → {added: n, skipped: [文件名...]}
DELETE /api/docs/{name}     → 204，同时令 revision++
GET    /api/docs/{name}/content → 全文
```
任何写操作（增/删）都必须使 F3 的 `revision` 自增。
