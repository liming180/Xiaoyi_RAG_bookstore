## 三、四条主链路（谁调谁）

### 3.1 建库 `POST /api/index`

```
api.api_index            app/api.py:103
  → store.build_index_async                app/store.py:88     起后台线程
      → store.build_index                  app/store.py:33
          → chunking.load_chunks           app/chunking.py:54  切分 + sha256
          → embedding.embed_texts          app/embedding.py:115 分批（batch=8）
          → json.dump + NamedTemporaryFile + replace（原子）
```

进度通过 `GET /api/index/progress` → `store.build_state()` 读 `_BUILD_STATE`。

### 3.2 提问 `POST /api/chat`

```
api.api_chat             app/api.py:149
  → chat.chat            app/chat.py:110
      ├─ mode == "both"：answer_once(rag) → 还原 history → answer_once(direct) → 再还原
      └─ 否则 answer_once             app/chat.py:22
            ├─ rag：chat._retrieve    app/chat.py:13
            │     → store.read_index      五层校验
            │     → embedding.embed_query
            │     → retrieval.rank_all / split_trace
            ├─ prompting.build_rag_messages
            ├─ llm.answer            app/llm.py:271
            ├─ prompting.strip_invalid_citations
            ├─ session.append_turn
            └─ store.append_log      JSONL
```

### 3.3 批量对照 `POST /api/batch/run`

```
api.api_batch_run        app/api.py:188
  → batch.run_batch_async                app/batch.py:66    后台线程
      → judging.load_eval_set            app/judging.py:61
      → 每题：batch._one(direct) → batch._one(rag)
          → session.new_session() 先清会话（避免上一题污染）
          → chat.answer_once(..., log=False)
      → judging.judge                    关键词初判
      → _STATE 更新（done/total/rows/stats）
```

`POST /api/batch/export` → `batch.export_csv` 写 `exports/对照测试_{时间戳}.csv`。

### 3.4 片段浏览 `GET /api/chunks`

```
api.api_chunks           app/api.py:118
  → chunking.load_chunks（按当前 cfg 的 size/overlap 重新切）
  → 按 source 过滤、按关键词子串过滤
  → 每条补 position = "第 {start+1} 字至第 {end} 字"
```

**注意**：这里不读 `index.json`，而是**用当前配置现场重切**。
好处是拓展B 的「第几字至第几字」永远与 `data/` 里的真实文件一致，
坏处是若配置与索引不一致（stale），片段编号会与索引里的不同——
这正是 F3「需要重新建库」要提示的状态。

## 四、依赖方向（不允许反向）

```
api  →  chat / batch / store / session / chunking / judging / prompting
chat →  store / session / chunking(间接) / embedding / retrieval / prompting / llm
batch→  chat / session / judging / settings
store→  chunking / embedding / settings
llm  →  embedding / retrieval? 否 / mockdata / prompting(常量) / settings
judging → settings
settings → （无内部依赖）
```

**`settings.py` 是叶子**，任何模块都可以 import 它，它不 import 任何内部模块。
**`app/api.py` 是唯一的入口层**，其余模块都不知道 HTTP 的存在——
所以 `tools/selfcheck.py` 可以完全不碰 `app/api.py` 就把 43 项全测完。

## 五、单进程内的并发

| 场景 | 机制 | 位置 |
| --- | --- | --- |
| 建库 | `_BUILD_STATE` + `_LOCK` + 后台线程 | `app/store.py:16-17`、`:88` |
| 批量对照 | `_STATE` + `_LOCK` + 后台线程，且 `stage=="running"` 时拒绝再次启动 | `app/batch.py:12-13`、`:68-69` |
| 会话 | `_STATE` + `_LOCK` | `app/session.py:12-13` |
| 日志 | 每次一行、独立文件，无需加锁 | `app/store.py:191` |

**刻意没有用 asyncio**：FastAPI 的同步 `def` 路由会被 Starlette 放进线程池执行，
对本项目的负载（单人使用、最多 20 个片段）完全够用，而线程模型比 async 更容易被学生读懂。

## 六、`app/__init__.py` 的 `__all__`

```python
__all__ = [
    "api", "batch", "chat", "chunking", "embedding", "judging",
    "llm", "mockdata", "prompting", "retrieval", "session", "settings", "store",
]
```

**注意这里没写 `store` 之外的文件操作模块**——所有落盘都在 `store.py`（索引/日志）、
`chunking.py`（读资料）、`api.py`（上传/删除）、`batch.py`（导出）四处，没有散落。
