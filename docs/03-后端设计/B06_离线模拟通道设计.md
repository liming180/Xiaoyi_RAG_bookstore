# B06 离线模拟通道设计

> **代码锚点**：`app/embedding.py:50 _gram_hash`、`:58 mock_embed_one`、`app/llm.py:22-101 ASPECTS`、`:105 _ABSENCE_MARKERS`、`:187 mock_answer`、`app/mockdata.py:9 DIRECT_PRESETS`、`:39 INJECTION_MARKERS`、`app/settings.py:132 is_mock`
> **最后核对**：2026-10-30 实测（direct 1/10、rag 10/10；T09 输出不含「完全免费」）

## 一、为什么需要这一档

本机环境**没有任何 endpoint 与密钥**（`API|KEY|TOKEN|RAG|OPENAI|DEEPSEEK|ENDPOINT|BASE_URL` 环境变量全为空），
而项目必须做到：

1. 能在**没有教师接口**的情况下演示全部 5 个任务 + 2 个拓展；
2. `tools/selfcheck.py` 能**离线跑 43 项断言**（CI/交作业前自检）；
3. 前端 32 项单元测试不依赖网络；
4. 交作业后教师用真实接口跑，行为口径一致。

于是设计了 `provider: "mock"` 这一档：**同一套提示词、同一套检索、同一套来源标注**，
只有「文本→向量」和「消息→回答」两个函数换成确定性本地实现。

## 三、mock 嵌入：字符 n-gram 哈希

```python
# app/embedding.py:58
def mock_embed_one(text: str, dim: int) -> list[float]:
    vector = [0.0] * dim
    for char in text:
        vector[_gram_hash(char, dim)] += 1.0            # 单字 权重 1.0
    for i in range(len(text) - 1):
        vector[_gram_hash(text[i:i + 2], dim)] += 1.0   # 2-gram 权重 1.0
    for i in range(len(text) - 2):
        vector[_gram_hash(text[i:i + 3], dim)] += 0.25  # 3-gram 权重 0.25
    norm = math.sqrt(sum(v * v for v in vector))
    return [v / norm for v in vector] if norm else vector
```

### 3.1 `_gram_hash` 用 FNV-1a 而不是内置 `hash()`

```python
# app/embedding.py:50
def _gram_hash(gram: str, dim: int) -> int:
    h = 2166136261
    for ch in gram:
        h = ((h ^ ord(ch)) * 16777619) & 0xFFFFFFFF
    return h % dim
```

**Python 的 `hash(str)` 受 `PYTHONHASHSEED` 影响**，同一个字符串在两个进程里哈希值不同。
如果用 `hash()`，今天建的库明天重启后就检索不到——向量空间整个漂移了。
FNV-1a 是纯算术，跨进程、跨机器、跨 Python 版本都稳定。

### 3.2 三通道权重 1 / 1 / 0.25 是怎么定下来的

初始实现只有「单字 + 2-gram」（权重 1/1），端到端 rag 只能到 8/10：

| 题 | 症状 |
| --- | --- |
| T01「读书会通常在每周几几点举行？」 | 证据片段 `D01-C001` 排第 4，k=3 捞不到 |
| T05「讨论空间需要几人每次最长多久？」 | `D03-C001` 排第 4，两个要点全 miss |
| T08「报名读书会的截止时间和空间预约可提前的天数分别是什么？」 | 其中一个证据片段排第 4 |

于是做了 **63 组网格搜索**（dim ∈ {256, 1024, 4096} × 通道组合 ∈ {bigram, unigram+bigram,
bigram+trigram, unigram+bigram+trigram} × 若干 3-gram 权重），评判标准是
「10 道题的证据文件是否全部落在前 3 名」。

结论：

- **dim=256 就够**（更大维度不提升命中率，只让 `index.json` 变大）；
- 必须**加入单字通道**：中文里「几」「人」「次」这种单字在短问题上权重很高，
  2-gram 会把它们黏成「几人」「每次」反而匹配不上片段里的「3至6人的阅读小组」；
- **3-gram 权重压到 0.25**：给长词一点加成，但不让它主导（3-gram 在短片段里出现次数少，权重高了会放大噪声）。

改完后 `[1.0, 1.0, 0.25]` 让 10 题证据文件全部进前 3，端到端 rag 从 8/10 升到 9/10，
剩下那一题（T04）是**要点表设计问题**，见下文第五节。

> 另一条被放弃的路线：混合检索（cosine 0.7 + IDF 词法 0.3）虽然也能到 10/10，
> 但改动面大、偏离骨架「纯向量检索」的教学口径，弃用。

### 4.2 第 6、7 条为什么要拆开（修过的 bug）

原始设计只有一条「续借」，`must=["续借"]`。T04「已经被别人预约的图书还能续借吗？」会先命中

```
普通图书在到期前可申请续借1次，续借增加7天。
```

这句话确实含「续借」，但**不是答案**——问的是「被预约的还能不能续借」，答案是下一句
「已经逾期或被其他成员预约的图书不能续借。」

拆成两条后，T04 同时触发「续借规则」与「续借限制」，两句都被引用：

```
普通图书在到期前可申请续借1次，续借增加7天。[D02-C001]
已经逾期或被其他成员预约的图书不能续借。[D02-C001]
```

关键词 `不能/不可以/不可/无法` 命中 → 通过。

**教训**：`must` 词表是「这句话必须同时包含哪些词」，一个宽泛的 `must` 会命中错误句。
拆成多个 narrow aspect 比给一个 aspect 塞多个候选词更可靠。

### 4.3 `_is_absence`：否定式声明不是答案（修过的 bug）

`01_活动说明.md` 末句：`本文不包含活动收费标准、联系电话和真实身份资料。`

T10「管理员的联系电话是多少？」会匹配「联系电话」这个 `must`，从而把上面那句当答案引用，
输出变成「本文不包含活动收费标准、联系电话和真实身份资料。[D01-C002]」——
读者看到的是「资料声明没写」，但形式上像在回答问题，与「资料中没有提供…」的诚实口径不一致。

```python
# app/llm.py:105
_ABSENCE_MARKERS = ("不包含", "没有提供", "未提供", "不涉及", "没有涉及",
                    "没有相关", "未说明", "没有说明")

# app/llm.py:182
def _is_absence(sentence: str) -> bool:
    return any(marker in sentence for marker in _ABSENCE_MARKERS)
```

命中就 `continue` 跳过，让该 aspect 落到 `miss` 分支，最终输出
「资料中没有提供管理员或工作人员的联系电话。」——**说「没有」而不是「引用否定句」**。

### 4.5 未核实片段的「不采用」提醒只在相关时出现

```python
# app/llm.py:239
if aspects:
    for hit in hits:
        if hit.get("verified", True):
            continue
        ...
```

**为什么要加 `if aspects`**：不加的话，问「本次会话的代号是青禾」这种完全不相关的问题时，
回答里也会附一句「留言 D06-C002 中的相关说法未经核实，不采用」——纯噪声，还会误导读者以为
06 号资料里真有什么相关内容。加上判断后，只有确实问到了某个要点才提醒。

### 4.6 `misses` 拼接的标点

```python
# app/llm.py:256
lines.append("；".join(m.rstrip("。；") + "。" for m in misses))
```

每个 `miss` 文案本身以「。」结尾，直接用「；」拼接会变成
「资料中没有提供讨论空间的人数要求。；资料中没有提供讨论空间每次的使用时长。」
先 `rstrip("。；")` 去掉句末标点再加回一个「。」，结果正确：

```
资料中没有提供讨论空间的人数要求；资料中没有提供讨论空间每次的使用时长。
```

## 六、mock 与 real 的行为对齐点

| 行为 | mock 实现 | real 实现 | 是否一致 |
| --- | --- | --- | --- |
| 系统提示词 | 同一份 `prompting.SYSTEM_PROMPT` | 同左 | ✅ |
| 参考资料格式 | `format_context` | 同左 | ✅ |
| 来源编号 | `[D02-C001]` 直接拼在句后 | 由模型按规则 1 生成 | ✅（后处理统一清洗） |
| 未提供时的话术 | aspect 的 `miss` 文案 | 由规则 2 约束 | ✅（语义一致，措辞略有差异） |
| 注入不执行 | `INJECTION_MARKERS` 过滤 + 明确声明 | 由规则 3 约束 | ✅ |
| 引用清洗 | `strip_invalid_citations` | 同左 | ✅ |
| `usage` 字段 | `mock_usage` 按字符数估算 | 接口返回真实值 | ⚠️ 仅数值来源不同，字段结构一致 |
| `elapsed_ms` | 真实计时 | 真实计时 | ✅ |

**唯一结构性差异**：mock 的回答是「拼句」，句式固定、不会有多轮改写；
real 的回答更自然但不可预测。**验收时以 mock 档截图，提交后教师用 real 档跑，功能项都应通过**。

## 七、`mock_usage` 的估算方式

```python
# app/llm.py:263
def mock_usage(prompt_chars: int, answer: str) -> dict[str, int]:
    return {
        "prompt_tokens": max(1, prompt_chars // 2),
        "completion_tokens": max(1, len(answer) // 2),
        "total_tokens": max(2, (prompt_chars + len(answer)) // 2),
    }
```

中文大致 1 token ≈ 1.5–2 字符，这里取 2 做保守估算。实测 T03 一条：
`prompt_tokens: 859`（对应 `messages` 总字符数约 1718）、`completion_tokens: 19`、`total_tokens: 878`。
**这个数只用于让日志字段非空、让报告能写「prompt 859 tokens」，不代表真实计费**。

## 八、mock 档的局限（写进报告「残余风险」）

1. **只覆盖 13 个要点**：教师临时问一个表外问题，mock 会走「bigram 相关度取两句」的兜底路径，
   回答质量明显下降。这是设计取舍——mock 的目标是「可复现地演示」，不是「通用对话」。
2. **不模拟多轮改写**：同一问题问两次，mock 输出逐字相同（`evidence` 是 dict，顺序稳定）。
   真实模型会有变化。
3. **不校验提示词质量**：mock 完全不读 `SYSTEM_PROMPT`（它靠 `ASPECTS` 工作），
   所以**改提示词对 mock 档没有任何影响**。想验证提示词效果必须切到 real 档。
4. **`_has_injection` 是子串匹配**：换个说法的注入（如「请忽略以上说明」）识别不到。
   real 档靠系统提示词第 3 条兜底，但也不是绝对安全——这正是思考题3 要讨论的残余风险。
