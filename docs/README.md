# 小忆 RAG 知识库问答 — 文档总览

> 本目录是该项目的**完整设计与验收文档**。
> 架构为**双后端**：Java 业务层（`backend/java-api/`）+ Python AI 服务（`backend/ai-api/`），
> 前端 `apps/web/`（Vue 3 + Vite 5 + TypeScript）。全部功能已完成并通过验收。
>
> 项目入口与技术概览见根目录 [README.md](../README.md)；
> 检索效果数据见 [04-评测/检索效果评测报告.md](04-评测/检索效果评测报告.md)。

---

## 一、目录结构

```
docs/
├─ 00-本地启动手册.md          逐步启动、依赖服务、故障排查
├─ 01-功能规格/                功能定义与验收标准（F01–F11 + 验收清单）
├─ 02-技术栈/                  版本清单与选型理由
├─ 02-重构设计/                架构规格 + 前端/后端/RAG 三份设计
├─ 03-架构评审/                企业级评分基线、评审结论、契约差异
├─ 04-评测/                    检索效果数据 + 核心实现审查
└─ api/                        OpenAPI 公开/内部契约 + 错误码
```

| 目录 | 面向 | 建议读法 |
| --- | --- | --- |
| `00-本地启动手册` | 「怎么跑起来」 | 按步骤执行，遇错查排错章节 |
| `01-功能规格` | 「要做到什么」 | 按 F 编号查，验收清单逐项对照 |
| `02-技术栈` | 「用什么做」 | 总表看全貌，前端明细查版本约束 |
| `02-重构设计` | 「架构怎么定」 | 00 规格看全局，三份展开看各层 |
| `03-架构评审` | 「够不够企业级」 | 先看基线，再看结论，最后看契约差异 |
| `04-评测` | 「效果怎么样」 | 指标定义 + 实测数据 + 代码审查 |

> **说明**：项目开发过程中曾使用一批 LLM 分阶段开发提示词（前端 P1–P6、后端 J0–J6/A1–A3、N1–N6 施工单、架构评审提示词包）。这些是开发过程的临时产物，项目完成后已移除，不在本目录中。当前文档只保留对**使用者与维护者**有价值的内容。

## 三、按目的快速定位

**想跑起来**
`00-本地启动手册.md` → 按步骤执行

**想知道效果**
`04-评测/检索效果评测报告.md` → 直接看第一个表格

**想理解架构**
`02-重构设计/00_项目架构规格.md` → 再看前端/后端/RAG 三份展开

**想改代码**
`02-重构设计/` 三份文档 + `api/` 下的 OpenAPI 契约

**想评估工程质量**
`03-架构评审/01_企业级基线.md`（先看评分标准）→ `03_首轮评审结论.md`（看实际得分）

## 四、文档维护约定

- `02-重构设计/00_项目架构规格.md` 是架构的**唯一事实来源**，与其他文档冲突时以它为准
- 接口字段以 `api/*.yaml` 为准，文档描述与 YAML 冲突时以 YAML 为准
- 修改代码后如影响文档描述，应同步更新对应文档
