## 一、node 版本是全套选型的起点

```
node -v   →  v21.7.1
npm -v    →  10.5.0
npm config get registry  →  https://registry.npmmirror.com
```

node 21 是**奇数版本**（非 LTS），很多新包直接把它排除在 `engines` 之外。实测过的约束：

| 包 | 版本 | `engines` | 21.7.1 是否满足 |
| --- | --- | --- | --- |
| vite | 8.3.5（latest） | `^20.19.0 \|\| >=22.12.0` | ❌ |
| vite | 6.4.5 | `^18.0.0 \|\| ^20.0.0 \|\| >=22.0.0` | ❌（21.x 不在任何区间） |
| **vite** | **5.4.21** | `^18.0.0 \|\| >=20.0.0` | ✅ |
| @vitejs/plugin-vue | 6.0.10（latest） | `^20.19.0 \|\| >=22.12.0` | ❌ |
| **@vitejs/plugin-vue** | **5.2.4** | `^18.0.0 \|\| >=20.0.0` | ✅ |
| vitest | 5.0.5（latest） | `^22.12.0 \|\| ^24 \|\| >=26` | ❌ |
| **vitest** | **2.1.9** | `^18 \|\| >=20` | ✅ |
| jsdom | 30.1.3（latest） | `^22.22.2 \|\| ^24.15 \|\| >=26` | ❌ |
| jsdom | 27.x / 28.x | `^20.19.0 \|\| ^22.12.0 \|\| >=24` | ❌ |
| **jsdom** | **26.1.0** | `>=18` | ✅ |
| **@vue/test-utils** | **2.5.1** | 无 | ✅ |
| **vue** | **3.5.44** | 无 | ✅ |

**结论**：`vue 3.5.44 + vite 5.4.21 + @vitejs/plugin-vue 5.2.4 + vitest 2.1.9 + jsdom 26.1.0 + @vue/test-utils 2.5.1`。
`package.json` 里全部写**精确版本（不带 `^`）**，避免下次 `npm install` 漂移到不兼容的小版本。

如果将来把 node 升到 ≥22.12，可以整体升到 vite 8 + plugin-vue 6 + vitest 5 + jsdom 30，
`package.json` 只改 6 行，源码不需要动（本项目没用任何 Vite 5 独有 API）。

`"type": "module"` 让 `vite.config.js` 与 `test/*.spec.js` 都能直接写 ESM。

四个脚本：

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `npm run dev` | Vite 开发服务器（默认 5173），`/api` 代理到 8765 | 改前端源码，要热更新 |
| `npm run build` | 产出 `dist`（index.html + assets/*.js + assets/*.css）；v1 在 `web/dist`，现行在 `frontend/dist` | **改完源码必须跑一次**，否则浏览器看到的还是旧 dist |
| `npm run preview` | 用 Vite 预览 dist | 只想确认构建产物，不想起 Python |
| `npm run test` | `vitest run`，4 个 spec 32 项 | 提交前跑一遍 |

## 三、`web/vite.config.js` 逐行解释（v1；现行版本是 `frontend/vite.config.ts`）

```js
export default defineConfig(({ command }) => ({
  plugins: [vue()],
  base: command === 'build' ? '/static/' : '/',
  build: { outDir: 'dist', assetsDir: 'assets', emptyOutDir: true, target: 'es2020' },
  server: {
    port: 5173,
    strictPort: false,
    proxy: { '/api': { target: 'http://127.0.0.1:8765', changeOrigin: false } },
  },
  test: { environment: 'jsdom', include: ['test/**/*.spec.js'], globals: false },
}));
```

### `base` 为什么要按 command 切

- **dev**：Vite 自己在 `http://localhost:5173/` 提供页面，资源必须按 `/` 取；
- **build**：产物交给 FastAPI 的 `/static` 挂载（`app/api.py:291`）托管，所以 `dist/index.html`
  里必须写成 `/static/assets/index-xxxx.js`，否则浏览器会去请求 `/assets/index-xxxx.js` → 404。

实测 `dist/index.html` 产物（2026-10-30）：

```html
<link rel="icon" type="image/svg+xml" href="/static/favicon.svg">
<script type="module" crossorigin src="/static/assets/index-D3qgyOn-.js"></script>
<link rel="stylesheet" crossorigin href="/static/assets/index-BfzlOT7M.css">
```

`web/index.html` 里 favicon 写的是 `/favicon.svg`，Vite 会按 `base` 自动改写成 `/static/favicon.svg`；
`web/public/favicon.svg` 会被原样拷到 `dist/favicon.svg`。
（以上为 v1 行为记录；`frontend/` 未使用 favicon，产物为 `frontend/dist/{index.html, assets/, mockServiceWorker.js}`。）

### `server.proxy`

开发时前端在 5173、后端在 8765，跨端口会被 CORS 拦。代理把 `/api/*` 转发到 8765，
前端代码里始终写相对路径 `/api/...`，**生产与开发共用同一份请求封装**（v1 是 `web/src/api.js`，现行是 `frontend/src/api/http.ts`）。

### `test.environment: 'jsdom'`

组件测试需要 `document`、`window.confirm`、`CSS.escape`（`SourceCard` 里用 `scrollIntoView`）。
`globals: false` 意味着每个 spec 都要显式 `import { describe, it, expect, vi } from 'vitest'`，
好处是不会有隐式全局，编辑器也能跳转。

## 四、`web/index.html`（v1 Vite 入口，13 行；现行入口为 `frontend/index.html`）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<link rel="icon" type="image/svg+xml" href="/favicon.svg">
<title>星河读书会 · 个人资料助手</title>
</head>
<body>
<div id="app"></div>
<script type="module" src="/src/main.js"></script>
</body>
</html>
```

与旧版 `web/legacy/index.html`（200 行、全部 DOM 手写）的区别：
**Vue 版骨架只有 `<div id="app">`**，所有界面由 `src/App.vue` 与 20 个组件渲染。
`lang="zh-CN"` 与 `charset="UTF-8"` 必须保留，否则中文会乱码。

## 六、构建产物体积与构成

| 文件 | 大小 | gzip | 内容 |
| --- | --- | --- | --- |
| `dist/index.html` | 470 B | — | 入口，引用两个 assets |
| `dist/assets/index-*.js` | 96.9 kB | 37.1 kB | Vue 3 运行时（约 60 kB）+ 本项目 21 个组件与 5 个 js 模块 |
| `dist/assets/index-*.css` | 10.0 kB | 2.7 kB | tokens + base + chat + table 四个 css 合并压缩 |
| `dist/favicon.svg` | 238 B | — | 从 `web/public/` 拷来 |

> 上表是 **v1 `web/` 的产物**。现行 `frontend/` 的产物规模：`vendor-ui 798.07 kB (gzip 252.10)` + `vendor 188.79 (gzip 68.32)` + `vendor-vue 113.80 (gzip 44.33)` + 各页面 chunk 与 CSS，合计约 1.6 MB。这是 Element Plus 全量引入的显式决策，理由见 `frontend/README.md`「已知边界」。

文件名带内容哈希（`index-D3qgyOn-.js`），**每次构建都会变**。
这意味着：改了源码但忘记 `npm run build`，浏览器会一直加载旧的 hash 文件——
`run.cmd` 在启动时检测 `frontend\dist\index.html` 是否存在并给出提示，
但**检测不出「dist 是旧的」**，所以改完前端一定要手动构建一次。

## 七、开发模式的两条命令

```powershell
# 窗口 1：后端（提供 /api/*）
py -3.12 -X utf8 -m app.api

# 窗口 2：前端热更新
cd frontend
npm run dev
# → http://localhost:5173
```

此时浏览 5173 即可，`/api` 由 Vite 代理。**不要**在 5173 上做验收截图——
验收要在 8765 上看构建产物，才是提交时的真实状态。
（`frontend/` 默认走 MSW mock，无需后端；要连真后端就把 `.env.development` 的 `VITE_USE_MOCK` 改为 `false`，详见 `frontend/README.md`。）
