## 三、`frontend/vite.config.ts` 逐段解释

```ts
export default defineConfig({
  plugins: [vue()],
  base: '/',
  resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } },
  server: {
    port: 5173,
    strictPort: true,
    proxy: { '/api': { target: process.env.VITE_PROXY_TARGET ?? 'http://localhost:8080', changeOrigin: true } },
  },
  preview: { port: 4173, strictPort: true },
  build: {
    outDir: 'dist',
    assetsDir: 'assets',
    emptyOutDir: true,
    target: 'es2020',
    sourcemap: false,
    chunkSizeWarningLimit: 850,
    rollupOptions: {
      output: {
        manualChunks: {
          'vendor-vue': ['vue', 'vue-router', 'pinia'],
          'vendor-ui': ['element-plus', '@element-plus/icons-vue'],
        },
      },
    },
  },
  test: {
    environment: 'jsdom',
    globals: false,
    include: ['test/**/*.spec.ts'],
    setupFiles: ['test/setup.ts'],
    css: false,
    restoreMocks: true,
    testTimeout: 10000,
    server: { deps: { inline: ['element-plus'] } },
  },
})
```

逐段理由：

- **`base: '/'` 而不是 v1 的 `/static/`**：v2 由 Java 网关或 nginx 把产物挂根路径，静态资源路径不能带 `/static` 前缀。v1 的 `/static/` 是因为 Python 单体用 `app.mount("/static", ...)`。
- **`manualChunks` 三刀**：`vendor-vue`（vue/router/pinia）、`vendor-ui`（element-plus + 图标）、其余自动归入 `vendor`。目的是让 `vendor-ui` 这份 797 kB 的大包在业务代码迭代时命中浏览器缓存。
- **`chunkSizeWarningLimit: 850`**：Element Plus 全量引入后 `vendor-ui` 是 797 kB（gzip 252 kB），默认 500 kB 阈值会打告警。这里**放宽阈值而非按需引入**是有意决策——`unplugin-vue-components` 新版要求 node ≥ 20.19，与锁定构建链不匹配，详见 `apps/web/README.md`「已知边界」。
- **`server.proxy['/api']`**：开发时把 `/api` 转发到 `VITE_PROXY_TARGET ?? http://localhost:8080`（Java 网关）。mock 模式下请求根本到不了代理层，被 MSW 拦掉。
- **`test.server.deps.inline: ['element-plus']`**：Element Plus 的 ESM 产物在 jsdom 里会被 vite 预打包成 cjs，导致组件内部的 `vue` 实例与测试里的不是同一个，出现「injection not found」。内联后走同一条模块图。
- **`test/setup.ts` 的三处环境补丁**（等宽理解这三条，否则测试会莫名挂死）：
  1. **给 `Blob.prototype` 补 `stream()` / `arrayBuffer()` / `text()`**：jsdom 的 Blob 没这三个方法，而 undici（MSW 底层）序列化 FormData 时会调 `blob.stream()`，拿到 `undefined` 后既不 resolve 也不 reject → 请求永久挂住。用 `FileReader` 实现，只在方法缺失时安装。
  2. **`URL.createObjectURL` / `revokeObjectURL`**：jsdom 无实现，CSV 导出会直接抛 `TypeError`。
  3. **`HTMLAnchorElement.prototype.click` 拦截带 `download` 属性的链接**：CSV 导出走 `<a download>` + `click()`，jsdom 会打 `Error: Not implemented: navigation`。只拦有 `download` 的，普通链接仍走原生逻辑，避免影响 RouterLink 用例。

## 四、`frontend/index.html`（14 行）

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>%VITE_APP_TITLE%</title>
```

## 五、安装与构建实测

```powershell
cd D:\VM1\Xiaoyi_RAG_bookstore\frontend
npm install          # added 422 packages in 4m
npm run build        # vue-tsc + vite build
```

`npm install` 的 `EBADENGINE` 警告来自 `balanced-match@4.0.4` 与 `brace-expansion@5.0.12`（都要求 node 18/20/>=22），是 eslint 的间接依赖，**不影响任何命令执行**。

## 七、开发的两条命令

**方式 A（默认，纯前端 mock）**：`npm run dev`，`.env.development` 里 `VITE_USE_MOCK=true`。
登录页点「一键进入演示」，28 个端点全部由 MSW（`apps/web/src/mocks/handlers.ts`）在浏览器里拦截，**不需要任何后端**。

**方式 B（连真后端）**：把 `.env.development` 的 `VITE_USE_MOCK` 改成 `false`，`npm run dev`。
此时 `/api` 走 `server.proxy` 转发到 `http://localhost:8080`（Java 网关），代理目标可用 `VITE_PROXY_TARGET` 覆盖。

> 5173 端口是开发服务器，**不做验收截图**。验收截图统一走 `npm run smoke` / `npm run regress`（生产构建 + 内置 stub API + 真 Chrome）。
