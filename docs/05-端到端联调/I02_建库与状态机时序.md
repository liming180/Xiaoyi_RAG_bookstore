# I02 建库与状态机时序

> **代码锚点**：`web/src/components/ChunkSettings.vue:26-54` → `web/src/store.js:142-159`（`buildIndex`/`pollIndex`）→ `app/api.py:243-256`（`api_config`）/`:103-114`（`api_index`/`api_index_progress`）→ `app/store.py:33-115`（`build_index`/`build_index_async`/`build_state`）/`:119-187`（`read_index`/`status`）
> **最后核对**：2026-10-30 实测（180/30 → 15 片段；120/30 → 23 片段；篡改 manifest → stale；重启进程 → ready 不重建）

## 一、状态机的全部状态

后端只有两个状态来源：`_BUILD_STATE["stage"]`（建库任务态）与 `status()["ready"]/["stale"]`（索引有效性）。二者正交，界面把它们合成三态徽章 + 一条提示。

```
                 ┌──────────────── 索引态（status()） ────────────────┐
                 │                                                    │
   ready=true  stale=false        ready=false stale=true     ready=false stale=false
   「知识库就绪 · 15 片段」        「需要重新建库」            「知识库未建库」
        (badge)                     (badge warn)                 (badge bad)
                 │                                                    │
                 └────────────────────────────────────────────────────┘

   建库任务态（_BUILD_STATE.stage）：idle → reading → embedding → done
                                              └────────→ error
```

判定代码（`app/store.py:175-187`）：

```python
try:
    index = read_index()
except AppError as exc:
    payload["message"] = str(exc)
    payload["stale"] = INDEX_FILE.is_file()   # ← 有文件但校验失败 = stale；没有文件 = 未建库
    return payload
payload.update({"ready": True, "chunks": len(index["chunks"]), "manifest": index["manifest"], …})
```

> 「从没建过库」与「建过但失效」的区别只有一行：`INDEX_FILE.is_file()`。删掉 `index.json` 就退回「未建库」，徽章从 `warn` 变 `bad`。

## 二、首次建库完整时序（180/30）

```
[浏览器] 点「重新建库」
   │  ChunkSettings.build()
   ▼
① actions.buildIndex(180, 30)                     web/src/store.js:142-152
   │  本地校验：50 ≤ size ≤ 1000 且 0 ≤ overlap < size
   │  失败 → toast「片段长度须在 50 至 1000 之间」/「重叠字数须满足 0 <= 重叠 < 片段长度」
   │
   ├─ POST /api/config {chunk_size:180, chunk_overlap:30}    app/api.py:243-256
   │     后端二次校验，写 config.json 白名单字段
   │
   └─ POST /api/index                                app/api.py:103-109
         store.build_index_async()  → 起 daemon 线程，立即返回 {started:true}
   ▼
② 后台线程 worker()                                app/store.py:96-111
   │  _BUILD_STATE = {stage:'reading', done:0, total:0}
   │  with _LOCK: build_index(progress)
   ▼
③ build_index()                                    app/store.py:33-85
   │  _chunk_settings(cfg)                → (180, 30)
   │  embedding.validate_embedding_config → mock 档直接过
   │  chunking.load_chunks(DATA_DIR,180,30)
   │      → 6 份资料 → 15 片段（01=2 02=2 03=2 04=3 05=3 06=3）
   │  batch = cfg["embedding_batch_size"] = 8
   │  for start in range(0,15,8):                       ← 两批：8 + 7
   │      embed_texts(...)  → 向量追加
   │      progress('embedding', min(start+8,15), 15)    ← 前端进度条推进
   │  校验条数 15 == 15；维度集合 {256} 唯一
   │  逐片段挂 chunk["embedding"]
   │  index = {"manifest": …, "chunks": …}
   │  NamedTemporaryFile(utf-8-sig, newline="\n", suffix=".tmp") → json.dump → replace()
   ▼
④ 前端轮询 GET /api/index/progress（每 300 ms）      web/src/store.js:153-160
   │  ChunkSettings 的 usePolling 在 stage !== 'running' 时停表
   ▼
⑤ 收尾
      actions.pollIndex() → !running → await actions.refresh()
      ChunkSettings 关掉 building，ready 时 toast
      「建库成功，文档 6 份，片段 15 条。」
```

### 实测进度序列

| 轮次 | `stage` | `done` | `total` |
| --- | --- | --- | --- |
| 1 | `reading` | 0 | 0 |
| 2 | `embedding` | 8 | 15 |
| 3 | `embedding` | 15 | 15 |
| 4 | `done` | 15 | 15 |

> `reading` 阶段的 `total=0` 会让进度条宽度算成 `0/0`。`web/src/store.js:36-52` 的 `indexHint` 里 `const pct = build.total ? … : 0` 做了保护，宽度按 0% 处理。

### 原子写为什么重要（`app/store.py:63-82`）

```python
with tempfile.NamedTemporaryFile(mode="w", encoding="utf-8-sig", newline="\n",
                                 dir=destination.parent, prefix=destination.name + ".",
                                 suffix=".tmp", delete=False) as stream:
    temporary = Path(stream.name)
    json.dump(index, stream, ensure_ascii=False, indent=2, allow_nan=False)
temporary.replace(destination)
```

- 临时文件与目标**同目录**（`dir=destination.parent`）——跨盘 `replace` 不是原子操作。
- 任何异常都走 `except (OSError, TypeError, ValueError)` → 「知识库保存失败，请检查目录和写入权限；**原文件未被替换**。」`finally` 里 `unlink(missing_ok=True)` 清临时文件。
- 因此前端看到的 `index.json` 永远是完整的旧版或完整的新版，不会出现「写了一半被读到」。

## 三、改分块设置 → 提示重新建库（表3 第②项）

这是**两层**提示，缺一不可。

### 第一层：前端 `dirty` 比对（不必等建库）

`web/src/components/ChunkSettings.vue:26-33`：

```js
const dirty = computed(() => {
  const status = state.status;
  if (!status || !status.ready) return null;
  const sizeChanged = Number(size.value) !== Number(status.chunk_size);
  const overlapChanged = Number(overlap.value) !== Number(status.chunk_overlap);
  if (!sizeChanged && !overlapChanged) return null;
  return `分块设置已改为 ${size.value}/${overlap.value}，与当前索引的 ${status.chunk_size}/${status.chunk_overlap} 不同，需要重新建库。`;
});
```

模板 `web/src/components/ChunkSettings.vue:80`：

```html
<p v-if="dirty" class="hint warn-text">{{ dirty }}</p>
```

样式 `web/src/styles/base.css:255-263` 的 `.hint.warn-text` 用琥珀底（`--amber-soft`）+ 琥珀字（`--amber`）+ `1px solid #eddfc2` 边框，与 `.notice` 同色系但更轻。

**实测**：把输入框从 180 改成 120，立刻出现「分块设置已改为 120/30，与当前索引的 180/30 不同，需要重新建库。」；改回 180 提示消失。

### 第二层：后端 manifest 比对（点建库后才触发）

`app/chunking.py:85-94` 的 manifest 由 5 个字段组成：

```python
def manifest_for(cfg, sources):
    return {
        "embedding_model": cfg.get("embedding_model", ""),
        "embedding_endpoint": cfg.get("embedding_endpoint", ""),
        "chunk_size": cfg.get("chunk_size"),
        "chunk_overlap": cfg.get("chunk_overlap"),
        "sources": sources,          # [{source, sha256}] 按文件名排序
    }
```

`read_index` 第 2 层用 `!=` 整体比较，任一字段变化即 stale。所以**改资料内容（sha256 变）、增删资料、改分块参数、换嵌入模型/端点**都会命中，无需额外逻辑。

### 重建后片段数必须增加

实测 6 份资料在不同参数下的片段数：

| 设置 | 01 | 02 | 03 | 04 | 05 | 06 | 合计 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **180 / 30**（默认） | 2 | 2 | 2 | 3 | 3 | 3 | **15** |
| **120 / 30** | 4 | 3 | 4 | 4 | 4 | 4 | **23** |

（字符数 304 / 294 / 307 / 369 / 388 / 369；滑窗 `start = end - overlap`，最后一窗 `end == len(text)` 即停。120/30 若按 CRLF 原始字节算会得到 25，但 `read_doc` 统一把 CRLF 归一成 LF，故实际 23。）

## 四、改资料 / 上传 / 删除 → stale

| 操作 | 后端动作 | 触发 stale 的机制 |
| --- | --- | --- |
| 上传 `.md`/`.txt` | `app/api.py:57-79` 写 `data/`（UTF-8 无 BOM、LF） | 新文件名进 `sources`，manifest 不等 |
| 删除资料 | `app/api.py:82-89` 删文件 | `sources` 少一条，manifest 不等 |
| 直接改 `data/` 里的文件 | 无后端动作 | 该文件 sha256 变，manifest 不等 |
| 改 `config.json` 的 `chunk_size`/`chunk_overlap` | 重启生效 | manifest 的 size/overlap 变 |
| 改 `embedding_model`/`embedding_endpoint` | 重启生效 | manifest 对应字段变 |

界面表现（`web/src/components/NoticeBar.vue:9-16`）：`stale && message` → 黄条 `<b>资料或分块设置已改变。</b>{message}`，同时 `TopBar` 徽章变「需要重新建库」。

> 上传/删除的响应里都带最新 `docs` 列表，但**不自动重建**——这是有意的：让「需要重新建库」这件事在界面上被看见，正是表3 的验收点。

## 五、重启进程 → 无需重建（表3 第③项）

`index.json` 落在项目根，进程重启后 `store.status()` 第一件事就是 `read_index()`。因为 `data/` 6 份资料与 `config.json` 都没变，manifest 与片段重切结果全等，直接 `ready=true`。

实测：

```powershell
Stop-Process -Id <旧 PID> -Force        # 关掉旧进程
py -3.12 -X utf8 -m app.api             # 重开
# 打开 http://127.0.0.1:8765
```

首屏 `GET /api/status` 直接返回 `ready=true, chunks=15`，徽章「知识库就绪 · 15 片段」，**不需要点任何按钮**。

> 注意 `_BUILD_STATE` 是内存态，重启后回到 `idle`；这不影响索引有效性，`indexHint` 走 `ready` 分支显示「建库成功，文档 6 份，片段 15 条。」。

## 六、并发与竞态

| 场景 | 保护 | 表现 |
| --- | --- | --- |
| 连点两次「重新建库」 | `app/store.py:90-91`：`stage in {"reading","embedding"}` → 抛「正在建库，请等待当前任务完成。」 | 第二次请求 400，界面 toast 该文案 |
| 建库中又发提问 | 建库持 `_LOCK`，但 `read_index` 不持锁 | 提问读到的仍是**旧** `index.json`（原子写保证完整），不会读到半成品 |
| 建库中又跑批量 | 批量走 `chat.answer_once` → `read_index` | 同上，用旧索引，结果自洽 |
| 连点两次「运行对照测试」 | `app/batch.py:68-69`：`stage == "running"` → 抛「正在运行对照测试，请等待当前任务完成。」 | 第二次 400 |
| 前端轮询定时器泄漏 | `usePolling` 用递归 `setTimeout` + `onUnmounted(stop)` | 组件卸载即停；`stage` 变非 running 时 `tick` 不再排下一轮 |

## 七、失败分支

| 现象 | 触发点 | 文案 | 处理 |
| --- | --- | --- | --- |
| size 越界 | `api_config` / `_chunk_settings` | 「片段长度须在 50 至 1000 之间。」 | 输入框 `min=50 max=1000` |
| overlap ≥ size | 同上 | 「重叠字数须满足 0 <= 重叠 < 片段长度。」 | 输入框 `min=0 max=999`，前端也拦一次 |
| 嵌入接口报错 | `embedding._real_embed` | 后端 HTTP 状态文案 | 检查 Key / 端点 |
| 返回条数不对 | `build_index:55-56` | 「嵌入接口返回的向量条数与片段数不一致，请教师核对接入层。」 | 教师侧接口问题 |
| 向量维度不一致 | `build_index:57-59` | 「嵌入向量维度不一致：[…]，请重新建库。」 | 换模型后必须重建 |
| 磁盘不可写 | `build_index:75-76` | 「知识库保存失败，请检查目录和写入权限；原文件未被替换。」 | 检查目录权限 |
| 空目录建库 | `chunking.load_chunks` | 「data 目录里没有 .md / .txt 资料。」 | 先上传资料 |

失败时 `_BUILD_STATE.stage='error'`，`indexHint` 显示「建库失败：{error}」，进度条停在上次位置。
