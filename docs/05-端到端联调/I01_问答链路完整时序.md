**五层校验**（`app/store.py:119-152`，任一层失败即抛 `AppError`，文案见 B07）：

1. 文件存在且能解析 → 否则「尚未建库，请先点击“重新建库”。」/「index.json 已损坏，请重新建库。」
2. `manifest` 与当前 `chunking.manifest_for(cfg, sources)` 全等 → 否则「资料、分块或嵌入模型已改变，请重新建库。」
3. 片段数一致 → 否则同上
4. 逐片段 `source/start/end/text/verified` 与原文**现场重切**结果逐字段相等 → 否则同上或「知识库片段字段不符，请重新建库。」
5. 全部向量维度唯一 → 否则「知识库向量维度不一致，请重新建库。」

**打分与排序**（`app/retrieval.py`）：

```python
def cosine(a, b):                      # app/retrieval.py:10-25
    if not a or not b or len(a) != len(b):
        raise AppError("向量维度不一致，无法计算相似度。")
    scale_a = max(abs(v) for v in a)   # 先按各自最大绝对值缩放
    scale_b = max(abs(v) for v in b)   # 防 1e308 级数值在平方时溢出
    if scale_a == 0 or scale_b == 0:
        raise AppError("向量全为零，无法计算相似度。")
    scaled_a = [v / scale_a for v in a]
    scaled_b = [v / scale_b for v in b]
    norm_a = math.sqrt(math.fsum(v * v for v in scaled_a))
    norm_b = math.sqrt(math.fsum(v * v for v in scaled_b))
    score = math.fsum((x / norm_a) * (y / norm_b) for x, y in zip(scaled_a, scaled_b))
    if not math.isfinite(score):
        raise AppError("无法计算有效相似度，请检查嵌入向量。")
    return max(-1.0, min(1.0, score))

def select_top_k(chunks, query_vector, k):   # :33-39
    scored = _scored(chunks, query_vector)   # 副本，不改原列表
    scored.sort(key=lambda chunk: (-chunk["score"], chunk["chunk_id"]))
    return scored[:k]

def rank_all(chunks, query_vector):          # :42-48
    trace = _scored(chunks, query_vector)
    trace.sort(key=lambda chunk: (-chunk["score"], chunk["chunk_id"]))
    for position, chunk in enumerate(trace, 1):
        chunk["rank"] = position
    return trace

def split_trace(trace, k):                   # :51-56
    hits = trace[:k]
    for chunk in trace:
        chunk["retrieved"] = chunk["rank"] <= k
    return hits, trace
```

```python
def format_context(hits):                       # :38-45
    blocks = []
    for hit in hits:
        label = UNVERIFIED_MARK if not hit.get("verified", True) else VERIFIED_MARK
        blocks.append(f'[{hit["chunk_id"]}] 来源：{hit["source"]}{label}\n{hit["text"]}')

def build_rag_messages(system_prompt, history, question, hits):   # :48-62

    if hits:
```

## 三、三种模式的差异（只在阶段 3 与阶段 4 分叉）

| 模式 | 阶段 3 检索 | 阶段 4 系统提示词 | 阶段 4 user 内容 | 日志 |
| --- | --- | --- | --- | --- |
| `rag` | 跑 | `SYSTEM_PROMPT`（七条） | `参考资料：…\n\n问题：…` | 1 条 |
| `direct` | **跳过**（`hits=[]`） | `DIRECT_PROMPT`（不引用、不标编号） | 只有 `question` | 1 条 |
| `both` | 跑两次（各清一次历史） | 各用各的 | 各用各的 | 1 条含 `direct_answer` |

`both` 的历史处理（`app/chat.py:126-134`）是这一块最容易写错的地方：

```python

direct_result = answer_once(question, "direct", k, log=False)
```

## 五、失败分支

| 现象 | 触发点 | 表现 | 处理 |
| --- | --- | --- | --- |
| 未建库 | `store.read_index` 第一层 | 400「尚未建库，请先点击“重新建库”。」 | 点「重新建库」 |
| 改了资料/分块未重建 | 第二层 manifest 不等 | 400「资料、分块或嵌入模型已改变，请重新建库。」 | 同上；界面同时出现 `.notice` 黄条 |
| 嵌入接口 401/403 | `embedding._real_embed` | 400 带 HTTP 状态 | 检查 Key 是否生效（见 B07 故障表） |
| 对话接口超时 | `llm.call_model` | 400「连接失败或超时：…；本次未加入会话历史。」 | **不入历史**，可直接重试 |
| k 越界 | `chat.chat` | 400「k 须为 1 至 5 的整数。」 | 滑块本身限 1–5，正常点不到 |
| 模型编了不存在的编号 | `strip_invalid_citations` | 不报错，静默剔除 + honesty 提示 | 无需处理，属预期防护 |
