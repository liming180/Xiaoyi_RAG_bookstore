# U02 状态管理与数据流

> **代码锚点**：`web/src/store.js:9-23 state`、`:28-52 kbBadge/indexHint`、`:54-249 actions`、`:162-198 send`、`web/src/api.js:7-19`
> **最后核对**：2026-10-30 实测（`web/test/store.spec.js` 9 项全通过；浏览器 both 模式 `lastTrace` 取 rag 侧）

## 一、一个 `reactive` 对象装下全部状态

```js
// web/src/store.js:9-23
export const state = reactive({
  status: null,        // /api/status 原始返回（含 session / docs / build / manifest）
  docs: [],            // 资料列表 [{name, chars, chunks, verified}]
  mode: 'rag',         // 会话模式 rag | direct | both
  k: 3,                // 取回片段数
  view: 'chat',        // chat | trace | chunks | batch
  lastTrace: [],       // 最近一次检索的完整排名（15 条）
  lastMessages: [],    // 最近一次实际发送的 messages
  batchRows: [],       // 批量对照行（10 条）
  batchState: null,    // /api/batch/progress 原始返回
  busy: false,         // 正在回答，防重入
  turns: [],           // 对话气泡 [{id, kind, status, payload, error}]
  chunks: { rows: [], total: 0, size: 0, overlap: 0, source: '', q: '' },
  flashChunkId: '',    // 点击编号后要高亮的片段
});
```

### 1.1 为什么没有拆成多个 store

13 个字段之间的关系非常紧：`mode`/`k` 来自 `status.session`，
`lastTrace` 由 `send()` 写入又要被 `TraceView` 读，
`batchRows` 与 `batchState.stats` 必须同步。

拆成 `useDocsStore` / `useChatStore` / `useBatchStore` 会产生两种坏情况：
要么每个 store 都要 import 别的 store（循环依赖），
要么 `send()` 要同时调三个 store 的 action（事务性丢失）。

**254 行一个文件，全部 action 在一个对象里**——这就是这个规模下的最优解。

### 1.2 哪些 `ref` 留在组件里

组件内部只保留**纯 UI 局部状态**，它们不需要跨组件共享：

| 组件 | 局部 ref | 用途 |
| --- | --- | --- |
| `Composer.vue` | `draft`、`box` | 输入框内容、DOM 引用（自适应高度） |
| `DocList.vue` | `hot`、`fileInput`、`uploading` | 拖入态、文件选择 DOM、上传中标志 |
| `ChunkSettings.vue` | `size`、`overlap`、`building` | 两个输入框的编辑值、建库按钮禁用态 |
| `ModelStatus.vue` | `chatKey`、`embedKey` | 密钥输入（提交后立即清空，绝不留在 store） |
| `ChunksView.vue` | `source`、`keyword`、`loaded` | 搜索条件、是否搜过一次（决定空态文案） |
| `BatchView.vue` | `running` | 按钮禁用态 |
| `TraceView.vue` | `loaded` | 是否已拉过消息 |
| `SourceCard.vue` | `root`、`open`、`flash` | DOM 引用、`<details>` 展开态、高亮态 |

**判据**：如果这个值「另一个组件也要看」或「要在测试里断言」，就进 store；否则留组件。

## 二、`api.js`：唯一的出网口

```js
// web/src/api.js:7-19
export async function api(path, options = {}) {
  const init = { ...options, headers: { ...(options.headers || {}) } };
  if (init.body && !(init.body instanceof FormData)) {
    init.headers['Content-Type'] = 'application/json';
    init.body = JSON.stringify(init.body);
  }
  const resp = await fetch(path, init);
  const data = await resp.json().catch(() => ({}));
  if (!resp.ok) {
    throw new Error(data.detail || `请求失败（HTTP ${resp.status}）`);
  }
  return data;
}
```

四个行为与旧版 `web/legacy/app.js:29` 逐条对齐：

1. **非 FormData 自动序列化**：上传用 `FormData`（浏览器自己设 `multipart/form-data; boundary=...`，
   手动设 `Content-Type` 会丢 boundary），其余自动 `JSON.stringify`；
2. **响应一律按 JSON 解析**：后端所有路由都返回 JSON；解析失败给 `{}` 兜底，不抛 SyntaxError；
3. **非 2xx 优先取 `detail`**：后端 `AppError` → `{"detail": "资料、分块或嵌入模型已改变，请重新建库。"}`，
   前端直接把这句中文显示给用户；没有 `detail` 才用 `请求失败（HTTP 500）`；
4. **`http.get/post/del` 三个薄包装**，没有 `put`/`patch`（后端也没用）。

**没有超时**：`fetch` 原生不支持 `timeout`，要的话得 `AbortController`。
本项目的请求都很快（mock 档 34 ms，real 档由 `timeout_seconds: 45` 在后端兜），不值得加。

## 四、四个最容易写错的地方

### 4.1 `send()` 必须 `reactive()` 包一层（真实踩到的 bug）

```js
// web/src/store.js:162-198（节选）
async send(question) {
  const text = String(question || '').trim();
  if (!text || state.busy) return null;
  state.busy = true;
  /* 注意：必须用 reactive() 包一层再 push。
   * state.turns 是 reactive 数组，读取时会返回代理，但后续我们持有的是原始对象 turn；
   * 直接改 turn.status 不经过代理，不会触发视图更新，界面会永远停在「正在回答…」。 */
  const turn = reactive({ id: ++turnSeq, kind: 'qa', question: text,
                          status: 'pending', payload: null, error: '' });
  state.turns.push(turn);
  try {
    const payload = await http.post('/api/chat', { question: text, mode: state.mode, k: state.k });
    turn.status = 'done';
    turn.payload = payload;
    ...
  } catch (err) {
    turn.status = 'fail';
    turn.error = err.message;
    throw err;
  } finally {
    state.busy = false;
    actions.refreshQuiet();
  }
}
```

**错误写法**（迁移时先这么写的）：

```js
const turn = { id: ++turnSeq, status: 'pending', ... };   // 原始对象
state.turns.push(turn);                                    // push 进 reactive 数组
turn.status = 'done';                                      // ✗ 改原始对象，不触发更新
```

`state.turns` 是 `reactive([])`，`push` 时 Vue 会把元素也包成代理**存进数组**，
但外部变量 `turn` 仍然指向**原始对象**。改原始对象不经过代理 → 不触发依赖收集 → 视图不动。

修法只有一条：**push 之前就用 `reactive()` 包好**，让外部持有的就是代理。
（或者 `state.turns[state.turns.length-1].status = 'done'`，但那样可读性差。）

修前 `web/test/app.spec.js` 的冒烟输出 `bubbles: ['bubble.user', 'bubble.assistant.pending']`，
修后 `['bubble.user', 'bubble.assistant']`——这条断言就是为这个 bug 加的。

### 4.2 `both` 模式的 `lastTrace` 取 rag 侧

```js
// web/src/store.js:182-187
if (payload.mode === 'both') {
  state.lastTrace = (payload.rag && payload.rag.trace) || [];
  state.lastMessages = [];
} else {
  state.lastTrace = payload.trace || [];
}
```

`both` 的响应结构是 `{mode:'both', rag:{...}, direct:{...}, 顶层字段取 rag 的}`。
顶层**也有** `trace`，但为了避免「以后后端改了顶层字段含义」的隐患，这里显式取 `payload.rag.trace`。

`lastMessages = []` 是因为 `both` 跑了两轮，`GET /api/logs/last` 只能拿到最后一轮（direct）的
messages，而 direct 的 messages 没有参考资料——显示出来会让人误以为 rag 也没带资料。
清空后「检索过程」第二张表显示空态 `还没有请求`，等用户单独问一次 rag 才有内容。

### 4.3 `buildIndex` 是两个请求，顺序不能反

```js
// web/src/store.js:142-150
async buildIndex(chunkSize, chunkOverlap) {
  const size = Number(chunkSize);
  const overlap = Number(chunkOverlap);
  if (!(size >= 50 && size <= 1000)) throw new Error('片段长度须在 50 至 1000 之间');
  if (!(overlap >= 0 && overlap < size)) throw new Error('重叠字数须满足 0 <= 重叠 < 片段长度');
  await http.post('/api/config', { chunk_size: size, chunk_overlap: overlap });
  await http.post('/api/index');
  return true;
}
```

1. 先本地校验（省一次网络往返就能提示，文案与后端逐字一致）；
2. `POST /api/config` 把新参数写进 `config.json`；
3. 再 `POST /api/index` 触发建库——**它读的是 `config.json` 里的参数**，顺序反了会用旧参数建库。

`web/test/store.spec.js` 有一项专门断言这个顺序：
`expect(calls.map(c => c.url)).toEqual(['/api/config', '/api/index'])`。

### 4.4 `dirty` 提示放在组件里而不是 store 里

```js
// web/src/components/ChunkSettings.vue:26-33
const dirty = computed(() => {
  const status = state.status;
  if (!status || !status.ready) return null;
  const sizeChanged = Number(size.value) !== Number(status.chunk_size);
  const overlapChanged = Number(overlap.value) !== Number(status.chunk_overlap);
  if (!sizeChanged && !overlapChanged) return null;
  return `分块设置已改为 ${size.value}/${overlap.value}，与当前索引的 ${status.chunk_size}/${status.chunk_overlap} 不同，需要重新建库。`;
});
```

它比对的是「输入框的编辑值」与「索引的实际值」。
`size`/`overlap` 是组件局部 ref（不进 store），所以 `dirty` 也只能在组件里算。

**这个提示是表3 第②项的硬要求**：把片段长度从 180 改成 120，界面必须立刻说「需要重新建库」，
不能等用户点按钮、等后端比对 manifest 才发现。旧版就是后者，属于验收缺口。

## 五、状态三态与文案函数

```js
// web/src/store.js:28-33
export function kbBadge(status) {
  if (!status) return { cls: 'badge', text: '知识库未就绪' };
  if (status.ready) return { cls: 'badge', text: `知识库就绪 · ${status.chunks} 片段` };
  if (status.stale) return { cls: 'badge warn', text: '需要重新建库' };
  return { cls: 'badge bad', text: '知识库未建库' };
}
```

```js
// web/src/store.js:36-52
export function indexHint(status) {
  const build = (status && status.build) || {};
  if (build.stage === 'running') {
    const pct = build.total ? Math.round((build.done / build.total) * 100) : 0;
    return { bar: `${pct}%`, text: `正在建库 ${build.done}/${build.total} 片段…` };
  }
  if (build.stage === 'error') return { bar: '0%', text: `建库失败：${build.error}` };
  if (status && status.ready) return { bar: '100%', text: `建库成功，文档 ${status.doc_count} 份，片段 ${status.chunks} 条。` };
  if (status && status.stale) return { bar: '0%', text: status.message || '需要重新建库。' };
  return { bar: '0%', text: '尚未建库，点击“重新建库”。' };
}
```

**为什么做成纯函数导出而不是 computed**：
`TopBar.vue` 与 `ChunkSettings.vue` 都要用 `kbBadge`/`indexHint` 的**不同部分**，
做成纯函数后两边各自 `computed(() => kbBadge(state.status))`，
既共享逻辑又不共享缓存——测试里也能直接 `expect(kbBadge({ready:true,chunks:15}).text).toBe('知识库就绪 · 15 片段')`。

## 六、数据流全景（三条链路）

### 6.1 首屏加载

```
App.vue onMounted
  └→ actions.refresh()
       └→ GET /api/status
            ├→ state.status = {ready, stale, chunks, doc_count, chunk_size, chunk_overlap,
            │                   session:{session_id,mode,k}, provider, mock, has_keys,
            │                   k_range, config, examples, build, docs, message, manifest}
            ├→ state.docs = status.docs
            ├→ state.mode = status.session.mode
            └→ state.k = status.session.k
                 ↓ 响应式渲染
    TopBar（徽章 + 状态行）、DocList（6 条）、ChunkSettings（180/30）、
    RetrievalSettings（k=3、rag）、ModelStatus（离线模拟）、Composer（4 个示例 chip）
```

### 6.2 建库

```
ChunkSettings @click=build()
  └→ actions.buildIndex(size, overlap)
       ├→ 本地校验
       ├→ POST /api/config {chunk_size, chunk_overlap}
       └→ POST /api/index                     ← 后端起线程，立刻返回
  └→ poller.start()  (usePolling, 300ms)
       └→ 每 300ms: actions.pollIndex()
            └→ GET /api/index/progress → {stage, done, total, docs, chunks, message}
                 ├→ state.status.build = data          → 进度条与文案实时更新
                 └→ stage !== 'running' 时 await refresh() → 徽章与片段数更新
```

### 6.3 提问

```
Composer @click=send()
  └→ actions.send(text)
       ├→ state.busy = true                    → 发送按钮变「正在回答…」并禁用
       ├→ state.turns.push(reactive({status:'pending'}))  → 立刻出现 pending 气泡
       ├→ POST /api/chat {question, mode, k}
       │    ├→ 200: turn.status='done'; turn.payload=payload
       │    │        state.lastTrace = payload.trace（both 取 rag.trace）
       │    │        state.status.session = payload.session
       │    └→ 4xx/5xx: turn.status='fail'; turn.error=detail
       └→ finally: state.busy=false; refreshQuiet()   ← 静默刷新状态，不打断对话
```

## 七、`web/test/store.spec.js` 的 9 项断言

| # | 断言 | 防的回归 |
| --- | --- | --- |
| 1 | `kbBadge` 三态文案 | 徽章文案被改动导致截图不符 |
| 2 | `indexHint` 四分支（running/error/ready/stale） | 建库提示文案或百分比算错 |
| 3 | `refresh()` 写入 status/docs/mode/k | 字段名改动后漏映射 |
| 4 | `buildIndex` 调用顺序 `['/api/config','/api/index']` | 顺序反了会用旧参数建库 |
| 5 | `buildIndex` 前端校验拦截（size=10 / overlap≥size） | 校验被删导致非法参数打到后端 |
| 6 | `send()` 成功后 `turn.status==='done'` 且 `busy===false` | 响应式丢失 / busy 卡死 |
| 7 | `send()` 失败后 `turn.status==='fail'` 且 `turn.error` 有值 | 错误被吞、气泡空白 |
| 8 | `send('')` 与 `send('   ')` 返回 null 且不请求 | 空问题打到后端 |
| 9 | `newSession()` 清空 `turns` 与 `lastTrace` | 清空对话没清干净 |
