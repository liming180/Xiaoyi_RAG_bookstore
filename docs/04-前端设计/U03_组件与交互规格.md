## 六、`text.js` 四个函数的行为细节

### 6.1 `answerNodes(text, citations)`

```js
const CITE_RE = /\[(\d+)\]|\[(D\d{2}-C\d{3})\]/g;
```

`byRef` **同时映射两种键**：`String(card.ref)`（`"1"`）与 `card.chunk_id`（`"D02-C001"`）。
所以模型写 `[1]` 或 `[D02-C001]` 都能定位到同一张卡。

**`CITE_RE.lastIndex = 0` 是必须的**：正则带 `g` 标志时 `lastIndex` 会在多次调用间保留，
不重置会导致第二次调用从上次位置开始，漏掉前面的编号。

### 6.2 `highlightTokens(question)`

```js
return String(question || '')
  .replace(/[？?。，,、；;：:！!（）()\s]/g, ' ')
  .split(' ')
  .filter((token) => token.length >= 2)
  .slice(0, 6);
```

**为什么要求 `length >= 2`**：单字（「的」「是」「几」）会在片段里命中太多次，满屏 `<mark>` 反而看不清。
**为什么 `slice(0,6)`**：问题很长时（如 T08 有 24 个字），取前 6 个词已经够定位。

### 6.3 `highlightSegments(text, question)`

先收集全部 `[start, end)` 区间，按起点排序，**再合并重叠区间**：

```js
hits.sort((a, b) => a[0] - b[0] || b[1] - a[1]);
const merged = [];
hits.forEach(([start, end]) => {
  const tail = merged[merged.length - 1];
  if (tail && start <= tail[1]) tail[1] = Math.max(tail[1], end);
  else merged.push([start, end]);
});
```

**解决的是旧版 `web/legacy/app.js:65` 的嵌套 bug**：旧版用 `String.replace` 逐个词替换成
`<mark>词</mark>`，如果「续借」和「借阅」都命中，第二个替换会把第一个的 `<mark>` 标签也包进去，
产生 `<mark>续<mark>借</mark></mark>` 这种非法嵌套。
区间合并后每个字符最多属于一个 `<mark>`。

### 6.4 `positionText` / `scoreWidth`

```js
export function positionText(chunk) { return `第 ${chunk.start + 1}–${chunk.end} 字`; }
export function scoreWidth(score) { return `${Math.max(4, Math.round(Number(score || 0) * 100))}%`; }
```

`positionText` 目前**只在测试里用**（模板里 `SourceCard` 直接拼 `card.start + 1`），
保留它是为了「后端 `position` 与前端算出来的必须一致」这条可测断言。
`scoreWidth` 的 `max(4, ...)` 是为了 0 分时得分条还能看见一小截。
