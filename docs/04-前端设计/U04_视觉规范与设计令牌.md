# U04 视觉规范与设计令牌

> **代码锚点**：`web/src/styles/tokens.css`（19 行）、`base.css`（444 行）、`chat.css`（143 行）、`table.css`（28 行）；旧版对照 `web/legacy/styles.css`（610 行）
> **最后核对**：2026-10-30 实测（4 个 css 共 634 行；浏览器渲染与示意网页一致，青绿主色 + 琥珀警示色）

## 一、设计基调

**「纸感 + 青绿」**：背景不是纯白而是带一点绿的暖灰（`#f8f9f7`），
卡片是纯白纸（`#ffffff`），侧栏再深一档（`#f1f4f0`），
主色是墨绿（`#276352`），警示色是琥珀（`#996429`）。
文字不用纯黑，最深是 `#253e38`（带绿的墨色），避免纯黑与纸感冲突。

**一句话判断标准**：所有颜色都往绿偏一点，没有一处是中性灰或纯黑。
唯一的例外是 `mark` 高亮的 `#fdf0c8`（米黄），因为它要在绿底上跳出来。

## 二、设计令牌全表（`web/src/styles/tokens.css`）

```css
:root {
  --bg: #f8f9f7;          /* 页面底色 */
  --paper: #ffffff;       /* 卡片/面板底 */
  --sidebar: #f1f4f0;     /* 侧栏底 */
  --ink: #253e38;         /* 最深文字（标题） */
  --text: #354740;        /* 正文 */
  --muted: #708079;       /* 次要文字 */
  --line: #e2e8e2;        /* 分隔线/边框 */
  --teal: #276352;        /* 主色 */
  --teal-dark: #1c4d3e;   /* 主色按下/深一档 */
  --soft: #eaf2ec;        /* 主色浅底（徽章、进度槽、cite 底） */
  --amber: #996429;       /* 警示文字（未核实、需要重建库） */
  --amber-soft: #faf1df;  /* 警示浅底 */
  --red: #ad5650;         /* 错误 */
  --red-soft: #fbefec;    /* 错误浅底 */
  --radius: 16px;         /* 面板圆角 */
  --shadow: 0 1px 2px rgba(37, 62, 56, .06), 0 8px 24px rgba(37, 62, 56, .06);
}
```

**14 个色值 + 2 个非色令牌，一共 16 个**。旧版 `web/legacy/styles.css:1-20` 一字不改搬过来，
理由是验收截图依赖这些色值——换一个色号，截图与示意网页就对不上了。

### 2.1 为什么 `--shadow` 用两层

```css
0 1px 2px rgba(37,62,56,.06),     /* 贴边的细影：让卡片"压"在纸上 */
0 8px 24px rgba(37,62,56,.06)     /* 远处的柔光：让卡片"浮"起来 */
```

单层阴影只能做到「有边界」或「有浮起感」其中之一。两层叠起来才有「一张纸放在另一张纸上」的效果。
阴影颜色用 `rgba(37,62,56,...)` 而不是 `rgba(0,0,0,...)`——**阴影也带绿**，与整体基调一致。

## 三、字体

```css
body {
  font-family: "Microsoft YaHei", "PingFang SC", system-ui, -apple-system, sans-serif;
  font-size: 14px;
  line-height: 1.65;
}
```

| 用途 | 字体栈 | 字号 |
| --- | --- | --- |
| 正文 | 上面这一串（微软雅黑 → 苹方 → 系统） | 14px / 1.65 |
| 代码、编号、位置 | `"Cascadia Mono", Consolas, monospace`（`.mono`） | 12px |
| 标题 `h1`（brand） | 继承正文栈 | 15px |
| 面板标题 `h2` | 继承正文栈 | 13px（见 `.panel-head h2`） |
| 次要说明 `.hint` | 继承 | 11.5px |
| 徽章 `.badge` | 继承 | 11px |
| 表格 | 继承 | 12.5px，`th` 12px |
| 摘录 `.card-excerpt` | 继承 | 12.5px |
| honesty 行 | 继承 | 11.5px |

**`.mono` 只用在四处**：片段编号（`D02-C001`）、原文位置（`第 1–180 字`）、
消息表的角色列（`system`/`user`）、资料原文气泡。
理由：这些内容「字符形状要能对齐」，等宽字体才能让 `D01-C001` 与 `D02-C001` 一眼看出差异。

**没有引入 Web Font**：微软雅黑 + 苹方覆盖了 Windows 与 macOS，
`system-ui` 兜 Linux。中文字体文件动辄 5 MB，加载会拖慢首屏，而且验收截图必须在**本机**拍。

## 四、间距与圆角

| 令牌/规则 | 值 | 用在哪 |
| --- | --- | --- |
| `--radius` | `16px` | `.panel`（侧栏四面板） |
| 面板内边距 | `14px` | `.panel` |
| 面板间距 | `margin-bottom: 14px` | `.panel` |
| 侧栏内边距 | `18px 16px 28px` | `.sidebar` |
| 主区内边距 | `16px 20px 40px` | `.view` |
| 顶栏内边距 | `12px 20px` | `.topbar` |
| 卡片圆角 | `12px` | `.card`、`.table-wrap`、`.drop` |
| 输入框圆角 | `12px` | `textarea.question`、`.field input` |
| 按钮圆角 | `10px` | `.btn` |
| 徽章圆角 | `999px`（胶囊） | `.badge` |
| 气泡圆角 | `14px`，靠说话人那一角 `5px` | `.bubble.user` / `.bubble.assistant` |
| 通用上边距 | `.mt8` = 8px、`.mt12` = 12px | 各处 |
| 元素间隙 | `gap: 8px`（表单/按钮组）、`12px`（网格）、`16px`（对话轮） | — |

**圆角有层级**：面板 16 > 卡片/表格 12 > 按钮 10 > 徽章 999。
数字越大表示「层级越高、越外围」。混用会让界面失去纵深。

**气泡的「小角」**：`.bubble.user { border-bottom-right-radius: 5px }`、
`.bubble.assistant { border-bottom-left-radius: 5px }`——靠说话人那一侧的角收小，
形成「箭头指向说话人」的视觉暗示，这是聊天气泡的标准做法。

## 五、六个语义色族与它们的唯一用途

| 色族 | 令牌 | 唯一用途 | 出现位置 |
| --- | --- | --- | --- |
| 主色 | `--teal` / `--teal-dark` / `--soft` | 「可用 / 已就绪 / 可点击」 | 徽章 `.badge`、按钮 `.btn.primary`、`cite`、`idx`、`score-bar > i`、`tr.cut` 虚线、品牌方块、用户气泡 |
| 警示 | `--amber` / `--amber-soft` | 「需要你注意」 | `.badge.warn`（未核实 / 离线模拟 / 需要重建库）、`.notice`、`.hint.warn-text`、`.card.unverified` 边框 |
| 错误 | `--red` / `--red-soft` | 「失败了」 | `.fail`（未通过初判 / 请求失败）、删除按钮 hover |
| 正文 | `--ink` / `--text` / `--muted` | 三级文字层级 | `ink` = 标题与强调，`text` = 正文，`muted` = 说明 |
| 线 | `--line` | 所有 1px 边框与分隔 | `.panel`、`.card`、`th/td`、输入框 |
| 纸 | `--bg` / `--paper` / `--sidebar` | 三层背景 | `bg` = 页面，`sidebar` = 侧栏，`paper` = 卡片 |

**规矩：同一个语义只用一个色族**。
比如「未核实」永远是琥珀，不用红——红是「错误」，未核实是「需要注意但不是错」。
「需要重新建库」也是琥珀——它是提示，不是失败。

## 六、`mark` 高亮的米黄

```css
.card-excerpt mark { background: #fdf0c8; color: var(--ink); padding: 0 1px; border-radius: 3px; }
```

`#fdf0c8` 是唯一不在令牌表里的颜色。原因：它需要**在青绿 + 白纸的界面里跳出来**，
用 `--amber-soft`（`#faf1df`）太淡，用 `--amber`（`#996429`）做背景又太深压住文字。
`#fdf0c8` 是琥珀色系里明度最高、饱和度适中的一档，配 `--ink` 文字对比度刚好。

`ChunksView.vue:74` 里还有一处内联 `style="background:#fdf0c8"`——同一个色值，
因为那个 `<mark>` 在表格里、`.card-excerpt mark` 选择器管不到。

## 七、状态徽章的三态配色（F3 核心）

| 状态 | class | 背景 | 文字 | 边框 | 文案 |
| --- | --- | --- | --- | --- | --- |
| 就绪 | `.badge` | `--soft` `#eaf2ec` | `--teal-dark` `#1c4d3e` | `#d8e6dc` | `知识库就绪 · 15 片段` |
| 需要重建 | `.badge.warn` | `--amber-soft` `#faf1df` | `--amber` `#996429` | `#eddfc2` | `需要重新建库` |
| 未建库 | `.badge.bad` | `--red-soft` `#fbefec` | `--red` `#ad5650` | `#f0d8d4` | `知识库未建库` |
| 幽灵 | `.badge.ghost` | 透明 | `--muted` | `--line` | `未引用知识库资料` |

**三种状态三种颜色是刻意的**：截图时要能一眼分辨。
「就绪」青绿、「需要重建」琥珀、「未建库」红——从「一切正常」到「你得动手」到「还没有」，
颜色强度递增。

## 八、表格的两条视觉规则（F8 核心）

```css
tr.retrieved td { background: #f4faf6; }              /* 前 k 条浅绿底 */
tr.cut td { border-bottom: 2px dashed var(--teal); }  /* 第 k 行虚线截取线 */
tr:last-child td { border-bottom: none; }
```

**`#f4faf6` 不在令牌表里**：它是 `--soft`（`#eaf2ec`）的浅化版，专门给表格行用。
用 `--soft` 会让整行显得太绿，与 `th` 的 `--soft` 底混在一起分不清表头与取回行。

**截取线画在「第 k 行」的底边**：`TraceView.vue:43` 的
`:class="{ retrieved: row.retrieved, cut: index === cut - 1 }"`。
k=3 时 `cut=3`，`index===2` 的第 3 行加虚线——**线以下是「没被取回」的部分**，
视觉上正好对应「k 是截取线」这个概念。

## 九、对话区三个特殊规则

### 9.1 用户气泡靠右、助手气泡靠左

```css
.bubble.user { align-self: flex-end; background: var(--teal); color: #fff; max-width: 78%; }
.bubble.assistant { background: var(--paper); border: 1px solid var(--line); box-shadow: var(--shadow); }
```

用户气泡**实心青绿**（对比强、面积小），助手气泡**白底带边框与阴影**（面积大、要读）。
`max-width: 78%` 防止长问题占满整行。

### 9.2 both 模式双列

```css
.answer-grid { display: grid; grid-template-columns: 1fr 1fr; gap: 12px; }
.answer-col { border: none; padding: 0; box-shadow: none; background: transparent; }
```

`1fr 1fr` 严格等宽——对照实验必须让两边一样宽，否则读者会下意识觉得宽的那边「更重要」。
`.answer-col` 去掉气泡的边框、内边距、阴影、背景，因为外层 `.answer-grid` 已经有列头分隔，
里面再套一层气泡会变成「气泡套气泡」。

窄屏（`max-width: 1080px`）时 `grid-template-columns: 1fr` 改成上下排列。

### 9.3 pending 气泡用斜体灰字

```css
.bubble.pending { color: var(--muted); font-style: italic; }
```

**不加 spinner、不加动画**：`正在回答…` 五个字 + 斜体灰已经足够表达「还没好」，
加动画反而在截图里变成一坨模糊的东西。

## 十、`dirty` 提示的琥珀框（表3第②项）

```css
.hint.warn-text {
  color: var(--amber);
  background: var(--amber-soft);
  border: 1px solid #eddfc2;
  border-radius: 9px;
  padding: 6px 9px;
  line-height: 1.55;
}
```

普通 `.hint` 是 11.5px 灰字无背景。`.warn-text` 加了琥珀底 + 琥珀边框 + 9px 圆角，
从「一行说明」变成「一块提示条」——因为它要求用户**做一件事**（重新建库），
不该和「当前为离线模拟档」这种纯信息混在一起。

**实测**：把片段长度从 180 改成 120，这块琥珀提示立刻出现；
改回 180，提示消失。

## 十一、`.toast` 的定位与动画

```css
.toast {
  position: fixed; right: 20px; bottom: 20px;
  background: var(--ink); color: #fff;
  padding: 9px 14px; border-radius: 11px; font-size: 12.5px;
  box-shadow: 0 8px 24px rgba(0, 0, 0, .18);
  opacity: 0; transform: translateY(8px);
  transition: opacity .2s, transform .2s;
  pointer-events: none; max-width: 420px; z-index: 40;
}
.toast.show { opacity: 1; transform: translateY(0); }
```

**`pointer-events: none`**：toast 在右下角，可能盖住「发送」按钮。
不加这句，toast 出现的 2.6 秒内用户点不到发送。

**`transform: translateY(8px)` → `0`**：从下往上滑入 8px，比纯淡入更有「弹出」感，
8px 刚好够感知又不夸张。

**唯一用纯黑阴影的地方**（`rgba(0,0,0,.18)`）：toast 是 `--ink` 深底，
用带绿的阴影看不出来，这里用中性黑更自然。

**`z-index: 40`**：目前最高层。没有模态框，所以不需要更高的值。

## 十二、空态文案的视觉

```css
.empty { text-align: center; color: var(--muted); font-size: 12.5px; padding: 26px 10px; }
```

七处空态全部用这一个 class：

| 位置 | 文案 |
| --- | --- |
| 资料列表 | `还没有资料` |
| 对话区 | `先在左侧建库，再提一个问题试试。` |
| 检索过程表1 | `还没有检索记录` |
| 检索过程表2 | `还没有请求` |
| 片段浏览（未搜过） | `选择资料或输入关键词` |
| 片段浏览（搜过无结果） | `没有匹配的片段` |
| 批量对照 | `还没有结果` |

**`padding: 26px 10px`** 让空态在表格区域里居中偏上，不是死居中——
死居中的空态看起来像「加载失败」，偏上一点才像「这里还没有内容」。

## 十三、响应式（唯一断点 1080px）

```css
@media (max-width: 1080px) {
  .app { grid-template-columns: 1fr; }
  .sidebar { border-right: none; border-bottom: 1px solid var(--line); max-height: 46vh; }
  .answer-grid { grid-template-columns: 1fr; }
}
```

三个改动：
1. 双栏改单栏（侧栏压到上方）；
2. 侧栏右边框改成下边框，并限高 46vh（防止侧栏吃掉整个屏幕）；
3. both 双列改单列。

**只设一个断点**：界面只有「双栏」和「单栏」两种合理形态，中间态没有意义。
`1080px` 是按「340px 侧栏 + 主区至少要 740px 才能放下 7 列表格」倒推出来的。

**验收截图在 1600×950 或 1800×950 拍**，所以这个断点只影响教师用笔记本现场演示。

## 十四、四个 CSS 文件的分工与行数

| 文件 | 行数 | 内容 | 搬自旧版 |
| --- | --- | --- | --- |
| `tokens.css` | 19 | `:root` 16 个令牌 | `styles.css:1-20` |
| `base.css` | 444 | 重置 / 布局 / 侧栏 / 资料列表 / 表单 / 主区 / 输入区 / 杂项 / 响应式 | `styles.css:22-354` + `:518-610` |
| `chat.css` | 143 | 对话 / 气泡 / both 双列 / cite / 来源卡 / honesty | `styles.css:356-490` |
| `table.css` | 28 | 表格 / 徽章 / 进度 / pass-fail / pre-wrap | `styles.css:492-516` |
| **合计** | **634** | — | 旧版 610 行 |

**多出 24 行**的构成：`.answer-col`（6 行，both 双列需要）、`.hint.warn-text`（9 行，表3第②项）、
`td.pre-wrap`（2 行，消息表需要）、`textarea.question` 选择器改名后多出的注释与换行（约 7 行）。

**为什么拆 4 个文件**：单文件 610 行改一处要滚很久；按「令牌 / 骨架 / 对话 / 表格」切开后，
改来源卡样式只看 `chat.css`，改表格只看 `table.css`。
`main.js` 里的导入顺序决定了层叠优先级：

```js
// web/src/main.js
import './styles/tokens.css';   // 变量，必须最先
import './styles/base.css';     // 骨架
import './styles/chat.css';     // 对话（可覆盖 base 的 .bubble）
import './styles/table.css';    // 表格（可覆盖 base 的 .badge）
```
