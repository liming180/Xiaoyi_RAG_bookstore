## 二、逐条契约细节

### 2.1 `GET /api/status` — 首屏唯一请求

响应字段（`app/api.py:28-47`）：

```json
{
  "ready": true, "stale": false, "chunks": 15, "doc_count": 6,
  "chunk_size": 180, "chunk_overlap": 30,
  "docs": [{"name":"01_活动说明.md","chars":304,"chunks":2,"verified":true}, ...],
  "session": {"session_id":"11a9005b1f12","mode":"rag","k":3},
  "provider": "mock", "mock": true, "has_keys": false,
  "k_range": [1,5],
  "config": {"model":"","embedding_model":"","endpoint":"","embedding_endpoint":""},
  "examples": ["读书会通常在每周几几点举行？", ...],
  "build": {"stage":"idle","done":0,"total":0,"docs":0,"chunks":0,"message":"","error":""},
  "message": "",
  "manifest": {"embedding_model":"","embedding_endpoint":"","chunk_size":180,"chunk_overlap":30,"sources":[...]}
}
```

**前端只读不写**：`refresh()` 把 `status`/`docs`/`mode`/`k` 四个字段映射进 state，
其余（`build`、`message`、`manifest`、`config`）留在 `state.status` 里供各组件 computed 读取。

**`examples` 的 4 条**（后端 `app/api.py:42` 硬编码）：
`读书会通常在每周几几点举行？`、`普通图书最多同时借阅几本借多久？`、
`参加读书会要交多少费用？`、`管理员的联系电话是多少？`
—— 分别对应「单文档事实」「数量+时长」「库外问题」「库外问题」，覆盖四类典型场景。

### 2.2 `POST /api/session/params` — 一次改一个

请求体是**部分更新**：`{k: 4}` 或 `{mode: "both"}`，不要求两个都给。

```python
# app/api.py:159-171
class ParamsIn(BaseModel):
    mode: str | None = None
    k: int | None = None
```

响应 `{session_id, mode, k}`。**注意 `session_id` 会变**——`app/session.py:29 set_params`
里只要 mode 或 k 真的变了，就换 `session_id` 并清空 history。
所以切 k 等于开一段新对话，`RetrievalSettings` 的「会话 xxx」提示会跟着变。

**为什么这样设计**：k 变了，上一轮的检索结果和回答就不再可复现；
mode 变了，direct 的编造答案混进 rag 历史会污染后续回答。清历史是最干净的做法。

### 2.3 `POST /api/docs/upload` — 唯一的 multipart

```js
// web/src/store.js upload()
const form = new FormData();
files.forEach((file) => form.append('files', file));
const data = await http.post('/api/docs/upload', form);
await actions.refresh();
return data;
```

**字段名必须是 `files`**（`app/api.py:57` 的 `files: list[UploadFile] = File(...)`）。
`api.js:9` 判断 `body instanceof FormData` 时**不设 `Content-Type`**——让浏览器自己写
`multipart/form-data; boundary=----WebKitFormBoundary...`，手动设会丢 boundary 导致后端解析失败。

**`skipped` 的四种文案**（`app/api.py:57-80`）：

| 情况 | 文案 |
| --- | --- |
| 后缀不是 `.md`/`.txt` | `{name}：只支持 .md / .txt` |
| 超过 2 MB | `{name}：超过 2MB` |
| 不是 UTF-8 | `{name}：不是 UTF-8 编码` |
| 正文为空 | `{name}：没有正文` |

前端把这些原样拼进 toast：`已添加 2 份，跳过 1 份：bad.exe：只支持 .md / .txt`。

### 2.4 `DELETE /api/docs/{name}` — 中文文件名要编码

```js
// web/src/store.js removeDoc()
await http.del(`/api/docs/${encodeURIComponent(name)}`);
await actions.refresh();
```

**`encodeURIComponent` 不能省**：文件名是 `01_活动说明.md`，不编码时 `fetch` 会把它
按 UTF-8 发出去，但路径里的 `/`、`?`、`#` 会被解释成路径分隔符或查询串。
FastAPI 侧 `{name:path}` 也需要编码后的形式才能正确还原中文。

### 2.5 `GET /api/docs/{name}/content` — 点文件名看全文

响应 `{name, chars, text}`。`chars` 是字符数（不是字节），`text` 是 CRLF 已归一为 LF 的正文。

前端 `openDoc` 拿到后 push 一个 `kind:'doc'` 的 turn：

```js
state.turns.push({ kind: 'doc', name: data.name, chars: data.chars, text: data.text });
state.view = 'chat';
```

**为什么不弹窗**：资料全文可能上千字，弹窗会挡住对话；塞进对话流后可以滚动、可以对照着提问。

### 2.6 `POST /api/config` + `POST /api/index` — 两个请求

```js
await http.post('/api/config', { chunk_size: size, chunk_overlap: overlap });
await http.post('/api/index');
```

`/api/config` 只写白名单 14 字段（`app/settings.py:89 save_config_patch`），
**绝不写 Key**——Key 只走 `/api/keys` 存内存。响应是 `{ok, config, status}`，
`status` 就是完整的 `/api/status` 结果（`app/api.py:256` 里直接 `api_status()`），
所以理论上一次 `/api/config` 就能刷新全部状态——但前端仍然走 `/api/index` → 轮询 → `refresh()` 那条路，
因为建库本身是异步的，参数改完状态还没变。

`/api/index` 立刻返回 `{started: true, state: {...}}`，真正建库在后台线程（`app/store.py:88 build_index_async`）。
所以必须轮询 `/api/index/progress`。

### 2.7 `GET /api/index/progress` — 建库轮询

响应 `{stage, done, total, docs, chunks, message, error}`：

| stage | 含义 | 前端表现 |
| --- | --- | --- |
| `idle` | 没在建 | 进度条 0% |
| `running` | 建库中 | 进度条 `done/total`，文案 `正在建库 3/15 片段…` |
| `done` | 建完了 | 进度条 100%，文案 `建库成功，文档 6 份，片段 15 条。` |
| `error` | 失败 | 文案 `建库失败：{error}` |

`pollIndex()` 返回 `stage === 'running'`，`usePolling` 据此决定是否继续。
结束时 `pollIndex()` 内部还会 `await refresh()` 一次，把徽章与片段数更新。

### 2.8 `POST /api/chat` — 最重要的一条

**请求**：`{question, mode, k}`，三个字段全给（前端不依赖后端默认值）。

**响应（单模式）**：

```json
{
  "mode": "rag",
  "answer": "已登记成员每人最多同时借阅4本普通图书，每本借期21天。[D02-C001]",
  "citations": [{"ref":1,"chunk_id":"D02-C001","source":"02_借阅规则.md","score":0.4677,
                 "start":0,"end":180,"verified":true,"text":"...","excerpt":"..."}],
  "trace": [{"rank":1,"chunk_id":"D04-C002","source":"04_期刊与工具书.md","score":0.5147,
             "verified":true,"retrieved":true,"excerpt":"..."}],
  "used_knowledge_base": true,
  "unverified_hit": false,
  "removed_citations": [],
  "elapsed_ms": 34,
  "usage": {"prompt_tokens":859,"completion_tokens":19,"total_tokens":878},
  "session": {"session_id":"11a9005b1f12","mode":"rag","k":3}
}
```

**响应（both）**：上面全部字段（取 rag 侧）+ 两个子对象：

```json
{ "mode": "both", "rag": {...}, "direct": {...} }
```

**`trace` 是 15 条**（全量排名），不是 3 条。`retrieved` 字段标出前 k 条，
`TraceView` 用 `filter(r => r.retrieved).length` 算出截取线位置。

**`citations` 是 k 条**（最多），按 `ref` 1..k 编号，与回答里的 `[1]`/`[2]` 对应。

**`removed_citations`** 是后端剔除的幻觉编号列表，非空时 honesty 行会显示
`已剔除无效编号 9、D09-C999`。

### 2.9 `GET /api/logs/last` — 最近一次实际发送的 messages

响应 `{messages[], question, answer, timestamp, session_id, mode, retrieved, usage, ...}`。
`messages` 是**真正发给模型的那个数组**（含 system prompt 与完整参考资料）。

前端只读 `data.messages`，渲染成「检索过程」第二张表。**空态**：`还没有请求`。

**注意**：`both` 模式下 `store.send()` 会把 `state.lastMessages = []`，
因为后端日志只记最后一轮（direct），而 direct 的 messages 没有参考资料，
显示出来会让人误以为 rag 也没带资料。

### 2.10 `GET /api/chunks?source=&q=` — 拓展B

两个查询参数都可选：

```js
const params = new URLSearchParams();
if (source) params.set('source', source);
if (q) params.set('q', q);
const data = await http.get(`/api/chunks?${params}`);
```

响应 `{chunks[], size, overlap, total}`，每项：

```json
{"chunk_id":"D02-C001","source":"02_借阅规则.md","start":0,"end":180,
 "verified":true,"text":"...","position":"第 1 字至第 180 字"}
```

**`position` 是后端算好的**（`app/api.py:137`），前端直接显示，不自己拼——
保证「片段浏览」与「来源卡」显示的位置文案完全一致。

**中文 query 必须编码**：`URLSearchParams` 自动做 percent-encoding，
所以 `?q=续借` 会变成 `?q=%E7%BB%AD%E5%80%9F`。如果手写模板字符串，
`fetch` 会因非 ASCII 字符抛 `TypeError`。

### 2.11 `POST /api/batch/run` + `GET /api/batch/progress` + `POST /api/batch/export`

**run**：`{k}`（可选，缺省用当前会话的 k），立刻返回 `{started:true}`。

**progress**：

```json
{"stage":"done","done":20,"total":20,
 "rows":[{"id":"T01","type":"单文档","question":"...",
          "direct_answer":"...","direct_pass":false,
          "rag_answer":"...","rag_pass":true,
          "rag_sources":"D01-C001", "keywords":"...", "answer_points":"...", "evidence":"..."}],
 "stats":{"total":10,"direct":1,"rag":10},
 "current":"", "error":"", "export_path":"exports\\对照测试_20261030-095617.csv"}
```

`done` 是 **20**（10 题 × 2 模式），`total` 也是 20；`stats.total` 是 **10**（题数）。
这两个数字不同，前端进度条用 `done/total`（20），徽章用 `stats`（10）。

**export**：`{name, path}`，写 `exports/对照测试_{YYYYmmdd-HHMMSS}.csv`（UTF-8 BOM）。

### 2.12 `POST /api/keys` — 密钥只进内存

请求 `{chat_key, embed_key}`。`embed_key` 空时后端复用 `chat_key`（`app/settings.py:108 runtime_keys`）。

响应 `{ok: true, has_keys: true}`。**没有任何接口能读回密钥**——`/api/status` 只有 `has_keys` 布尔值。

前端提交后立刻清空两个输入框：`chatKey.value = ''; embedKey.value = '';`

## 三、错误处理统一路径

```js
// web/src/api.js:15-17
if (!resp.ok) {
  throw new Error(data.detail || `请求失败（HTTP ${resp.status}）`);
}
```

后端三种错误都收敛到 `detail`：

| 来源 | 状态码 | `detail` 示例 |
| --- | --- | --- |
| `AppError`（业务错） | 400 | `资料、分块或嵌入模型已改变，请重新建库。` |
| `HTTPException`（404 等） | 404 | `找不到资料 99_不存在.md` |
| pydantic 校验失败 | 422 | `detail` 是数组，前端会拿到 `[object Object]` |

**pydantic 422 的 `detail` 是数组**（`[{loc, msg, type}]`），`new Error(array)` 会变成
`[object Object]` 这种不可读文案。实际使用中前端每个请求都自己给了正确类型
（`{k: Number}`、`{mode: String}`），所以 422 只在「有人手工改代码」时出现，不值得为它加格式化逻辑。

## 四、轮询的两个间隔与理由

| 轮询 | 间隔 | 理由 |
| --- | --- | --- |
| 建库 `pollIndex` | **300 ms** | 15 片段建库约 1–2 秒（mock 档更快），300 ms 能出 4–6 次进度更新，肉眼可见「在动」 |
| 批量 `pollBatch` | **400 ms** | 10 题 × 2 模式 = 20 次问答，每轮约 30–40 ms，总耗时 1 秒级；400 ms 够了，太快会给后端加压 |

**两者都是「上一轮结束后才排下一轮」**（`usePolling` 用递归 `setTimeout`），
所以慢请求不会堆积。
