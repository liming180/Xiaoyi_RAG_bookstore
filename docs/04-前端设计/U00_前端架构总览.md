# U00 前端架构总览

> **代码锚点**：`web/index.html`、`web/vite.config.js`、`web/src/main.js`、`web/src/App.vue`、`web/src/store.js`、`web/src/api.js`、`web/src/components/`（17 个 SFC）、`web/src/components/views/`（4 个视图）
> **最后核对**：2026-10-30 实测 `npx vite build` 35 modules / ~2.5s、`npx vitest run` 4 files / 32 tests 全通过、浏览器 0 console error

## 一、一句话

**单页 Vue 3 应用，零路由、零状态库、零 UI 框架**：一个 `reactive` store 管全部状态，
`fetch` 直接打 FastAPI 的 `/api/*`，构建产物 `web/dist` 由后端 `/static` 挂载、
`GET /` 返回 `dist/index.html`。

## 二、构建与运行拓扑

```
开发态（两条命令）
  cd web && npm run dev          →  http://127.0.0.1:5173
      vite dev server，/api 走 proxy → http://127.0.0.1:8765
  py -3.12 -X utf8 -m app.api    →  http://127.0.0.1:8765（只提供 /api，页面 503）

生产态（一条命令）
  cd web && npm run build        →  web/dist/
  py -3.12 -X utf8 -m app.api    →  http://127.0.0.1:8765
      GET /            →  FileResponse(web/dist/index.html)
      GET /static/*    →  StaticFiles(web/dist)
```

`web/vite.config.js` 的关键三行：

```js
base: command === 'build' ? '/static/' : '/',
build: { outDir: 'dist', target: 'es2020' },
server: { proxy: { '/api': 'http://127.0.0.1:8765' } },
```

**`base` 为什么必须切**：开发态页面在根路径，`/src/main.js` 直接可用；
构建后页面由 FastAPI 在 `/` 返回，而静态资源挂在 `/static`。
如果不切 `base`，`dist/index.html` 会请求 `/assets/index-xxx.js` → 404 → 白屏。
Vite 在构建时把 `web/index.html` 里的 `/favicon.svg`、`/src/main.js` 全部改写成 `/static/...`。

实测 `web/dist/index.html`（470 B）：

```html
<link rel="icon" type="image/svg+xml" href="/static/favicon.svg">
<script type="module" crossorigin src="/static/assets/index-D3qgyOn-.js"></script>
<link rel="stylesheet" crossorigin href="/static/assets/index-BfzlOT7M.css">
```

**`check_dir=False` 为什么必须加**：`app/api.py:291`

```python
app.mount("/static", StaticFiles(directory=str(WEB_DIST), check_dir=False), name="static")
```

`StaticFiles` 默认 `check_dir=True`，目录不存在时**在 import 阶段就抛 RuntimeError**。
而 `tools/selfcheck.py`、`run.cmd`、`pytest` 都会 `import app.api`——
一旦有人先 clone 再跑自检（还没 `npm run build`），整个后端直接起不来。
`check_dir=False` 让挂载变成惰性，访问 `/static/*` 时才 404。
`GET /` 另有兜底：`dist/index.html` 不存在时返回 503 中文提示页（`app/api.py:262 _MISSING_DIST`）。

### 3.2 依赖方向（严格单向）

```
main.js → App.vue
            ├→ components/*（只 import store / utils / composables）
            │     └→ store.js（唯一的状态与副作用入口）
            └→ store.js
                  ├→ api.js（唯一出网口）
                  └→ composables/useToast.js
```

**没有组件直接 `fetch`**，也**没有组件之间互相传状态**。
唯一的例外是父子传值：`ChatTurn → AnswerBlock`（传 `payload`/`question`）、
`AnswerBlock → SourceCard`（传 `card`/`index`/`question`）——都是单向 props，没有 emit 回传。

## 四、三条 Vue 化改造（相对旧版原生 JS 的关键差异）

### 4.1 彻底不用 `v-html`

旧版 `web/legacy/app.js` 把用户问题、资料原文、模型回答全部 `esc()` 后拼进 `innerHTML`。
`esc()` 一旦漏一处就是 XSS——而**资料原文与模型回答都是不可信输入**（资料里就埋着注入样本）。

新版把「拼 HTML」换成「返回节点数组」：

```js
// web/src/utils/text.js:16
answerNodes('答案[D02-C001]，[9] 不存在', citations)
// → [
//   {type:'text', value:'答案'},
//   {type:'cite', raw:'[D02-C001]', chunk_id:'D02-C001'},
//   {type:'text', value:'，[9] 不存在'},   ← 无效编号当纯文本，不造假来源
// ]
```

模板里 `v-for` 渲染（`web/src/components/AnswerText.vue:20-28`）：

```html
<template v-for="(node, index) in nodes" :key="index">
  <span v-if="node.type === 'cite'" class="cite" :data-chunk="node.chunk_id" @click="focus(node.chunk_id)">{{ node.raw }}</span>
  <template v-else>{{ node.value }}</template>
</template>
```

浏览器永远把 `node.value` 当文本，**不存在「忘了转义」这条路径**。
高亮同理：`highlightSegments()` 返回 `[{text, hit}]`，`hit` 为真才渲染 `<mark>`。

### 4.2 状态与副作用集中在 `store.js`

组件里没有任何 `ref` 保存业务数据（只有纯 UI 局部状态：`draft`、`hot`、`building`、`running`）。
所有请求、所有状态写入都在 `web/src/store.js` 的 `actions` 里。

好处直接体现在测试上：`web/test/store.spec.js` 9 项全部只 import `store.js` + 桩 `fetch`，
不需要挂载任何组件就能验证「buildIndex 先 POST /api/config 再 POST /api/index」
「send 失败后 busy 复位」这类时序问题。

### 4.3 轮询改用递归 `setTimeout`

旧版两处 `setInterval`（建库 `web/legacy/app.js:500`、批量 `:461`）只在成功路径清定时器，
异常或用户切视图时会持续打后端。

```js
// web/src/composables/usePolling.js:11
export function usePolling(task, interval = 300) {
  ...
  async function tick() {
    if (stopped) return;
    let go = false;
    try { go = await task(); } catch (err) { stop(); throw err; }
    if (stopped) return;
    if (go) handle = setTimeout(tick, interval);   // 上一轮结束后才排下一轮
    else { active.value = false; handle = null; }
  }
  function start() { stop(); stopped = false; active.value = true; handle = setTimeout(tick, interval); }
  onUnmounted(stop);                                // 组件卸载自动停
  return { active, start, stop };
}
```

三个改进点：
1. **不重叠**：`setTimeout` 在 `await task()` 之后才排，慢请求不会堆积（`setInterval` 会）；
2. **异常即停**：`catch` 里 `stop()` 再抛，不会无限重试打爆后端；
3. **卸载即停**：`onUnmounted(stop)`，切走视图不留幽灵定时器。

## 五、一次提问在前端经过哪些文件

```
Composer.vue  @click=send()
  └→ store.actions.send(text)
       ├→ state.busy = true
       ├→ state.turns.push(reactive({status:'pending'}))     ← 界面立刻出现「正在回答…」
       ├→ api.js http.post('/api/chat', {question, mode, k})
       ├→ turn.status='done'; turn.payload=payload
       ├→ state.lastTrace = payload.trace（both 时取 payload.rag.trace）
       └→ finally: state.busy=false; refreshQuiet()
            ↓ 响应式触发重渲染
ChatView.vue  v-for state.turns
  └→ ChatTurn.vue  按 turn.status 选 pending / fail / AnswerBlock
       └→ AnswerBlock.vue
            ├→ AnswerText.vue  answerNodes → 文本节点 + cite 徽标
            └→ SourceCard.vue  ×N  得分条 / 位置 / 摘录 / 原文
```

**关键细节**：`store.js:169` 必须 `reactive({...})` 包一层再 push。
`state.turns` 是 reactive 数组，读取时返回代理；但代码里后续持有的是**原始对象** `turn`，
直接改 `turn.status` 不经过代理，**不会触发视图更新**，界面会永远停在「正在回答…」。
这是迁移过程中真实踩到的 bug，修法与原因都写在源码注释里。

## 六、与后端的分工边界

| 职责 | 前端 | 后端 |
| --- | --- | --- |
| 分块 | ❌ | ✅ `chunking.chunk_text` |
| 向量化 / 检索 / 排序 | ❌ | ✅ `embedding` / `retrieval` |
| 拼提示词 | ❌ | ✅ `prompting.build_rag_messages` |
| 引用编号清洗 | ❌ | ✅ `prompting.strip_invalid_citations` |
| 判分 | ❌ | ✅ `judging.judge` |
| 会话历史 | 只存 `session_id` 与 mode/k | ✅ `session._STATE` 持有 history |
| 参数校验 | ✅ 提交前拦一次（提示快） | ✅ 落盘前再拦一次（可信） |
| 视觉呈现 | ✅ 全部 | ❌ |

**唯一「双份」的是分块参数校验**（`web/src/store.js:145-146` 与 `app/api.py:246-250`），
文案逐字一致：`片段长度须在 50 至 1000 之间` / `重叠字数须满足 0 <= 重叠 < 片段长度`。
前端拦是为了不用等一次网络往返就能提示，后端拦是因为「前端可以被绕过」。

## 七、为什么不引入 Pinia / Vue Router / UI 框架

| 候选 | 不引入的理由 |
| --- | --- |
| **Pinia** | 全局只有一份状态，没有模块划分需求。`reactive()` + 一个 `actions` 对象就是最小可用方案，254 行可读性反而更好。Pinia 会引入 `defineStore`/`storeToRefs` 一层间接，对「学生要能讲清代码」这个目标不利。 |
| **Vue Router** | 4 个视图是 `v-show` 切换的并列面板，**没有 URL 语义**（不需要分享链接、不需要前进后退、不需要刷新保持）。上路由只会增加 `router-link`/`<router-view>` 的间接层。 |
| **Element Plus / Naive UI** | 视觉已在 `docs/04-前端设计/U04_视觉规范与设计令牌.md` 定稿（青绿 + 琥珀的纸感风格），引入组件库要推翻重做主题，且会让「来源卡」「得分条」「检索过程第 k 行虚线」这些自定义结构变得别扭。 |
| **Tailwind** | 同上；且现有 `base.css` 443 行已经把布局写完，改成原子类不会减少总行数。 |
| **axios** | 只有 5 种调用形态（GET / POST-JSON / POST-FormData / DELETE / 带 detail 的错误），25 行 `fetch` 封装够用。axios 会多 13 KB 且要处理 `interceptors`。 |
| **TypeScript** | 没有类型体系要维护；接口返回结构都在 `docs/03-后端设计/B05_API接口契约.md` 里定死了，加 TS 只增加构建复杂度（还要配 `vue-tsc`）。 |
| **ESLint / Prettier** | 单人项目，代码风格已经统一（2 空格、单引号、无分号风格混用除外）。加 lint 链会让 `npm install` 从 119 包涨到 300+ 包。 |
