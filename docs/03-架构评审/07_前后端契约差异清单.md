## 适配完成标准

1. Compose 缺少 `AUTH_JWT_SECRET` 或 `INTERNAL_TOKEN` 时在配置阶段失败；两者显式注入后全栈可启动。
2. 前端正常流程删除 demo 一键登录、固定用户身份和旧演示文案，改用真实登录结果。
3. 前端不生成或修改 `submission_key`、`generation`；这些字段只在 Java/Python 内部链路中维护。
4. 两个真实账号完成上传、建库、问答、会话和反馈隔离验收。
5. `pnpm run gate` 仍通过，但必须额外完成真实后端与真实浏览器验收。

## 验收期间修复的真实缺陷

1. `backend/java-api` 的 `RealAiServiceClient` 未固定 HTTP 版本：JDK HttpClient 对 `http://` 默认先发 h2c 升级，uvicorn 的 h11 直接回 400，表现为「建库一律 503/50301」。已加 `.version(HttpClient.Version.HTTP_1_1)`。
2. Python `GET /internal/v1/ingest/{task_id}` 不回传 `chunks`，Java `persistChunks` 拿到空列表，资料永远停在 `UPLOADING`。已补 `ingest.task_chunks()` 与 `InternalChunkItem` 契约。
3. 空语料下 `rebuild` 把 Python 的 400 翻成 50301。已改为直接收敛为 `SUCCEEDED/done/100` 并清空本人上一代片段。
4. Python 五个入库阶段毫秒级跑完，Java 1s 轮询看不到中间态。已加 `ingest_stage_delay_ms`（默认 0）。
5. 前端 `createConversation` 请求体是 `{title:{title}}`，真实后端 400/40001，而 MSW 宽松解析让 302 个用例全绿。已修正签名与调用方，并让 mock 同样严格 + 补回归用例。
6. uvicorn 默认 5 秒回收空闲 Keep-Alive 连接，而 JDK HttpClient 的连接池会继续复用它们，下一次 `POST /internal/v1/documents/parse` 直接 `Connection reset` → 50301「AI 服务不可用」。表现为「点一次重建失败、再点一次又好」的随机 503。已修两处：uvicorn 启动加 `--timeout-keep-alive 75`；`parseDocuments` 改走幂等重试（Python 按 `(user_id, submission_key)` 去重，重放拿同一个 task_id，不会重复切片段）。
7. `IndexServiceImpl` 触发建库失败的日志只打 `getMessage()`，网络失败在日志里只剩一句「Python AI request failed」，分不清超时/连不上/对端关连接。已补异常本体。
8. `infra/docker/compose/docker-compose.localdb-prebuilt.yml` 的 java healthcheck 写成 `exec 3<>/dev/tcp/...`，而 `eclipse-temurin:21-jre` 的 `/bin/sh` 是 dash，不支持该重定向（`cannot create /dev/tcp/127.0.0.1/8080: Directory nonexistent`），容器恒 unhealthy 并阻塞 frontend 启动。已改用镜像自带的 `curl -fsS http://127.0.0.1:8080/api/v1/health`，并按实测冷启动 49.3s 设 `start_period: 90s`。
9. compose 的 java-backend 缺 `SPRING_PROFILES_ACTIVE=gate-probe`：`GateProbeController` 不注册，J1 十条错误码用例全部 404。
10. compose 的 java-backend 缺 `STORAGE_ROOT` 与 `../backend/java-api/storage` 挂卷：资料写在容器内，J2 的「磁盘上应有 `backend/java-api/storage/<id>/<name>`」断言必挂。
11. compose 的 `INGEST_STAGE_DELAY_MS` 只给了 java-backend，而该变量只被 `backend/ai-api/app/config.py` 读取，Java 侧不读，J4 的五阶段用例只看到 `parsing` 与 `done`。已挪到 python-ai。
12. `frontend/Dockerfile.runtime` 缺配套 `.dockerignore`：`frontend/.dockerignore` 第 2 行排除 `dist`，BuildKit 会把它应用到 `Dockerfile.runtime`，报 `failed to compute cache key: "/dist": not found`。

## 本机 MySQL 直连模式（三端跑在本机进程，不涉及 Docker）

`infra/docker/compose/docker-compose.yml` 仍是交付形态，但验收不依赖镜像仓库：三端直连本机 MySQL 8.0，表结构由 Java 启动时的 Flyway V1–V7 建立，与 compose 内 java-backend 跑的是同一份迁移 SQL。

```powershell
copy deploy\local-mysql.env.example deploy\local-mysql.env   # 填 MYSQL_PASSWORD + AUTH_JWT_SECRET + INTERNAL_TOKEN
python tools\local_mysql.py prepare      # 只 CREATE DATABASE IF NOT EXISTS，不建表
python tools\local_mysql.py up --timeout 180   # Python(8000) + Java(8080)，Flyway 自动建表
python tools\local_mysql.py verify       # 双账号 + 13 表 + Flyway 全 success
python tools\local_mysql_smoke.py        # 上传→建库→轮询→A/B 隔离断言
python tools\local_mysql.py down         # 只停本工具进程，不停 MySQL，不删库
```

硬约束与 compose 一致：库名须以 `_gate`/`_test` 结尾、`AUTH_JWT_SECRET` ≥ 32 UTF-8 字节、`INTERNAL_TOKEN` 非空、bootstrap 口令 12–72 字节，缺项即 fail-fast。`INGEST_STAGE_DELAY_MS=1200` 给黑盒用例留出五阶段观测窗口；`P7_SPRING_PROFILES=gate-probe`（默认）才注册 `/__gate/throw`。

## 容器栈模式（三端在 Docker，数据库在宿主机）

`infra/docker/compose/docker-compose.localdb-prebuilt.yml` 是 A 项实际取证的拓扑：java/frontend 走 `Dockerfile.runtime` 直接拷宿主机已构建的 jar 与 dist（容器内不跑 Maven、不跑 `npm ci`），python-ai 走 `backend/ai-api/Dockerfile`，数据库连宿主机 8.0.39。

```powershell
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS xiaoyi_rag_local_gate CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
python tools\local_mysql_grant_container.py
cd backend/java-api; mvn -q -DskipTests package; cd ..
cd frontend; npm run build:only; cd ..
$env:MYSQL_USER_FOR_CONTAINER = 'xiaoyi'
docker compose -f infra/docker/compose/docker-compose.localdb-prebuilt.yml --env-file deploy/local-mysql.env up -d --build
python tools\compose_smoke.py     # 报告 test-artifacts/compose-smoke.json
```

跑 pytest 前必须设 `NO_PROXY=127.0.0.1,localhost`：Windows 系统代理 `127.0.0.1:7890` 会被 httpx 读取，`ProxyOverride` 里的 `127.*` 对 httpx 不生效，不设就会拿到 502。

## 全容器模式（mysql 也在容器里，2026-11-06 实测）

`mysql:8.0` 拉取成功后可跑交付形态 `infra/docker/compose/docker-compose.yml`：

```powershell
python tools\docker_deploy.py --mode stack up --smoke     # 169.3s，四容器 healthy
python tools\check_stack_db.py                            # tables=13 / flyway 1..7 全 success
python tools\docker_deploy.py --mode stack down
```

- 容器内 MySQL 从空库起：`Successfully applied 7 migrations to schema xiaoyi_rag_local_gate, now at version v7 (execution time 00:04.788s)`、`Started XiaoyiRagApplication in 24.416 seconds`。
- `check_stack_db.py` → `tables=13`、`flyway=1:1,2:1,3:1,4:1,5:1,6:1,7:1`、`documentsByUser=2=1,3=1`、`chunksByUser=2=1`。
- mysql 镜像拒绝 `MYSQL_USER=root`（entrypoint 直接 exit 1），容器业务账号必须走 `MYSQL_USER_FOR_CONTAINER`；`local-mysql.env` 需同时给 `MYSQL_USER_FOR_CONTAINER` 与 `MYSQL_ROOT_PASSWORD`。
- mysql 容器不发布 3306，冒烟脚本在 stack 模式自动加 `--db-via-container`，走 `compose exec mysql`（口令用 `MYSQL_PWD` 传，不进进程参数）。
