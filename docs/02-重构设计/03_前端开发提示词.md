# 前端开发提示词手册（LLM 分阶段开发 + 门禁制）

> 版本：v1.0（2026-10-30）
> 用途：把《前端文档》《00_项目架构规格》转译成**可直接投喂给 AI 编程工具（Claude Code / Cursor 等）的分阶段提示词**。
> 铁律：**每阶段做完必须过门禁（测试通过），门禁不过禁止进入下一阶段**——把"门禁提示词"发给 LLM，由它自证。
> 配套文档（开发时作为上下文投喂）：`00_项目架构规格.md` §4/§7、`前端文档.md`、`01-功能规格/F01~F10`、`docs/api/openapi-public.yaml`（P1 产出后）。

## 0. 总使用说明（每次开新会话先发这条）

### 提示词 P-0：项目上下文装载（每个新会话第一条）

```text
你是资深前端工程师，负责"星河读书会知识库助手"的 v2 前端开发。请先阅读以下文档再回答任何问题：
1. docs/02-重构设计/00_项目架构规格.md —— 重点 §4 前端结构、§7 接口契约、§7.5 SSE 事件协议
2. docs/02-重构设计/前端文档.md —— 页面/组件/交互的完整设计
3. docs/01-功能规格/ 中与我当前阶段相关的 F 编号文档 —— 验收标准

全局约束（贯穿所有阶段，违反即返工）：
- 技术栈：Vue 3 (<script setup>) + TypeScript + Vite + Pinia + Vue Router + Element Plus + Axios
- 工程结构：feature-first（features/chat、features/knowledge、features/eval、features/auth），组件禁止直接使用 axios，统一走 src/api/ 抽象层
- 服务端数据不进 Pinia；Pinia 只放全局客户端状态（会话列表、系统状态灯）
- 后端基址 /api/v1（vite dev 用 proxy 转发）；前端永远不知道 /internal 的存在
- 所有接口类型从 docs/api/openapi-public.yaml 生成（openapi-typescript），禁止手写接口类型漂移
- 每个模块以 index.ts 作为唯一对外出口，禁止深层导入
- 编码 UTF-8 无 BOM + LF；密钥/地址走 .env，不入仓库

请确认你已理解上述约束，并复述当前阶段目标（我接下来会发）。
```

### 门禁机制（你的操作规则，不用发给 LLM）

每个阶段结束时，依次执行并**全部通过**才算关门：

| 门禁项 | 命令/方式 | 标准 |
|---|---|---|
| Lint | `npm run lint` | 0 error |
| 类型检查 | `npm run typecheck`（vue-tsc） | 0 error |
| 单元测试 | `npm run test`（vitest） | 全部通过 |
| 阶段自查 | 发送该阶段的"门禁提示词" | LLM 逐条自检并报告 |
| 手动验收 | 按该阶段附带的 F 编号操作一遍 | 界面行为符合验收标准 |

**门禁提示词模板**（每阶段末尾附有专属版）：

```text
阶段 {N} 开发完成。现在执行门禁自查：
1. 运行 npm run lint 与 npm run typecheck，贴出结果，0 error 才算过；
2. 运行 npm run test，贴出通过数；如有失败先修复再重跑，禁止带病进入下一阶段；
3. 对照以下清单逐条自检（来自 {F 编号/本阶段验收标准}），每条回答"通过/不通过+原因"：
   {清单}
4. 全部通过后输出"门禁通过"，否则输出未通过项与修复计划。
你没有全部通过之前，我不会发布下一阶段任务。
```

## 1. 阶段 P1：工程骨架 + Mock 数据层（前端先行开发的根基）

> 背景：Java 后端尚未开发，前端必须**对着契约跑在 mock 上**。用 MSW（Mock Service Worker）按 openapi 契约拦截请求返回假数据。

### 提示词 P1-A：初始化工程

```text
【任务】在仓库根目录新建 frontend/（Monorepo 目标结构；旧 web/ 目录已随本次重构删除）：
1. 用 Vite 创建 Vue3 + TS 工程：frontend/，装 pinia、vue-router、element-plus、axios、msw、@openapitools/openapi-typescript-cli（或 openapi-typescript）；
2. 建立 feature-first 目录骨架（只建空目录与 index.ts 占位，不写业务）：
   src/api/{http.ts,modules/}、src/features/{auth,chat,knowledge,eval}/、src/stores/、src/app/{router,layout}/、src/components/、src/types/、src/constants/
3. 配置：vite proxy 把 /api 转发到 http://localhost:8080；路径别名 @→src；eslint + prettier + vue-tsc 脚本（lint/typecheck/test 三条命令可用）；
4. 生成 openapi 类型占位：docs/api/openapi-public.yaml 暂不存在时，先手写 src/types/api.d.ts 最小模型（Result<T> 包装、Citation、ChatStreamEvent、IndexStatus、DocumentMeta、Conversation、Message），并在文件头注释"openapi-public.yaml 就绪后由生成器替换"；
5. App.vue 仅渲染"工程骨架 OK"页面。

【约束】不写任何业务组件；不动已归档的旧 web/（已于 2026-11-01 删除）；所有新文件 LF。

【完成标准】npm run dev 能打开占位页；lint/typecheck 通过；目录树与上述一致。
```

### 提示词 P1-B：HTTP 层 + MSW Mock

```text
【任务】实现 api 抽象层与 mock：
1. src/api/http.ts：Axios 实例，请求拦截器注入 JWT（从 localStorage 读，暂无登录则空）；响应拦截器统一拆包 Result<T>（code!==0 抛业务错误对象），401 跳登录占位，503+degraded 触发全局事件；
2. src/api/modules/ 四个模块文件（auth/chat/knowledge/eval），函数签名按《前端文档》§4 与规格 §7.3 全量定义（含 chat/stream 的 SSE 封装函数，用 fetch + ReadableStream 解析 event/data 帧，返回 async iterator）——本阶段只定义签名与类型，SSE 实现允许简化；
3. MSW handlers 按"契约 mock"覆盖全部端点：返回符合类型的最小假数据（含 1 个演示会话、6 份文档、T03 风格的一条带 3 个 citation 的回答）；SSE 端点用 ReadableStream 模拟完整事件序列 status→retrieval→token×N→done；
4. vitest：为 http 拦截器与 SSE 解析器写单测（至少：拆包正常/业务错误/degraded 三例；SSE 帧解析含粘包与未知事件忽略两例）。

【完成标准】npm run test 全过；MSW 开启时任何组件调 api 都能拿到假数据。
```

### P1 门禁提示词

```text
（套用 §0 门禁模板，清单如下）
- lint / typecheck / test 三绿；
- 目录树符合 feature-first；无任何组件直接 import axios；
- MSW 下 curl 或临时按钮可拿到 Result 包装的假数据；
- SSE 解析器对 status/retrieval/token/done/error 五类事件均能解析，未知事件不抛错。
```

## 3. 阶段 P3：对话页（对应 F04/F05/F06/F07/F08/F10，本产品核心，体量最大）

分三小步，每步一个提示词，**每步跑一次 vitest 再进下一步**。

### 提示词 P3-A：对话流与消息渲染（F04/F05）

```text
【任务】实现 features/chat 的消息展示链路：
1. useConversation composable：加载会话消息（GET /api/v1/conversations/{id}/messages）→ MessageList 渲染用户/助手气泡；
2. SourceRef 组件：把回答文本中的 [Dxx-Cxxx] 编号渲染为可点击徽标，点击弹出引用卡（doc_title / heading_path / excerpt 高亮 / score / kind 徽标，kind=summary 显示"🌐 全局汇总"）；引用卡内容来自 message.citations；
3. 幻觉引用清洗：文本中出现但 citations 里不存在的编号渲染为灰色不可点（沿用 v1 F05 规则）；
4. 消息元信息：耗时、degraded 警示条（done.degraded=true 时）；
5. vitest：编号解析（含表格内编号）、引用卡开关、幻觉编号置灰三组用例。

【验收（F04/F05）】mock 会话里 T03 回答显示"4本、21天"且编号可点开引用卡；引用卡 excerpt 与编号对应。
```

### 提示词 P3-B：SSE 发送与双加载态（F04）

```text
【任务】实现提问链路：
1. ChatInput：Enter 发送 / Shift+Enter 换行 / maxlength 1000；发送后 useChat 管理 SSE 流（P1-B 的封装）；
2. 双加载态：status 事件驱动阶段文案（检索中→重排中→生成中，aria-busy）；token 增量追加渲染；done 后刷新消息（落库版替换流式版）并触发 citations 渲染；
3. 异常路径：error 事件 → 错误气泡 + 重试按钮；网络断开 → 同；degraded → 警示条；
4. 中断：生成中可点"停止"（AbortController）；
5. vitest：事件序列驱动状态机的用例（正常/中途 error/未知事件/degraded）。

【验收（F04）】发送后立即出现阶段提示且输入禁用；流式文字逐段出现；完成后引用徽标可点。
```

### 提示词 P3-C：模式/k/追问/清空（F06/F07/F10 + 套餐 B1）

```text
【任务】补齐对话页控制项：
1. 模式切换 segmented（查资料/直接/对照，默认查资料）+ k 下拉（1-10 默认 3），与输入框同行；对照模式：一次请求返回两份结果（mock 返回 both 结构）分左右栏展示；
2. 追问 chips：done.suggestions 渲染在气泡底部，点击即发送该问题；无 suggestions 不渲染且不报错；
3. 清空对话（F10）：会话菜单"清空本轮"→ 确认弹窗 → DELETE /api/v1/conversations/{id}/messages → 本地清空，保留 mode/k；
4. 示例问题 chips（来自常量文件，如"读书会什么时候举行？"）；
5. vitest：模式/k 变更进请求体、清空确认流、suggestions 兼容缺失字段。

【验收（F06/F07/F10）】三模式可切换且请求体带 mode/k；对照模式两栏对照；清空后消息区为空但输入区设置保留。
```

### P3 门禁清单
- 三步各自的 vitest 全过 + lint/typecheck；
- 手动过 F04（等待状态/示例问题/回答）/F05（来源五要素）/F06（三模式）/F07（k 生效）/F08（下阶段）/F10（清空）中除 F08 外全部条目；
- **特别检查**：所有用户输入（问题、追问 chips）经过 XSS 检查——渲染层无 v-html 裸用。

## 4. 阶段 P4：知识库页（对应 F01/F02/F03 + 拓展B）

```text
【任务】实现 features/knowledge：

【验收（F02）】mock 任务从 0→100% 走完全部阶段；改参数未建库时状态灯变黄（联动 P2）。
```

## 8. 阶段总览（投喂顺序）

```
P-0 上下文装载（每个新会话）
└─ P1 骨架+Mock 层   → 门禁①
   └─ P2 布局+状态(F03) → 门禁②
      └─ P3 对话页(F04-F07,F10) → 门禁③   ← 核心体量，分 A/B/C 三小步
         └─ P4 知识库页(F01-F03,拓展B) → 门禁④
            └─ P5 评测页(F09,套餐) → 门禁⑤
               └─ P6 登录+打磨+全量回归 → 最终门禁
```

> 与后端的衔接：P1-P6 全程跑在 MSW 上，不阻塞 Java 开发；Java `/api/v1` 就绪后，只改 .env 关 mock 做一轮真联调回归（复用 P6 清单），即完成前后端集成。
