## 1. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3 + `<script setup>` | 上手快、生态成熟；与现有 HTML 原型迁移成本低 |
| 构建 | Vite + TypeScript | 类型约束 API 模型，引用/轨迹等复杂结构不易写错 |
| UI 组件 | Element Plus | 表单、进度条、表格开箱即用（建库面板/评估结果用得上） |
| 状态 | Pinia | 会话、建库状态、配置三块全局状态 |
| 请求 | Axios 封装 + 原生 fetch stream（SSE） | 对话走 `POST /api/v1/chat/stream` SSE；其余 REST |
| 路由 | Vue Router | 页面见 §3 |

> 备选 React + Antd 亦可，契约不变；本文按 Vue3 表述。

## 2. 页面结构（3 页 + 全局）

```
AppShell（顶栏：会话切换/系统状态灯/配置入口）
├── /chat          对话页（默认，占产品 80% 使用）
├── /knowledge     知识库页（资料管理 + 建库 + 片段浏览）
└── /eval          评测页（批量对照测试 + 历史报告）
```

## 3. 页面与功能映射

### 3.1 对话页 /chat（F04/F05/F06/F07/F08/F10）

**布局**：左侧会话列表（折叠），主区对话流，底部输入区。

- **对话流**：用户/助手气泡；助手气泡内：
  - 回答正文，来源编号渲染为可点击徽标 `[D02-C001]`（F05）；
  - 点击徽标 → 弹出引用卡：`doc_title / heading_path / excerpt（start-end 定位高亮）/ score`，并可跳转知识库页对应片段；
  - 底部折叠"检索过程"面板（F08）：双路召回列表、RRF 分数、重排分数、各阶段耗时——默认收起，调试时展开；
  - `degraded: true` 时显示"知识库暂不可用，本次为直接回答"警示条。
- **输入区**：
  - textarea：Enter 发送 / Shift+Enter 换行，maxlength 1000；
  - 模式切换（F06）：`知识库 / 直接 / 对照` 三态 segmented control，对照模式回答分左右两栏展示；
  - k 选择（F07）：下拉 1~10，默认 3，与模式同一行；
  - 发送后进入 SSE 双加载态：`status` 事件驱动"检索中/重排中/生成中"（F08 阶段可视化），`token` 事件流式渲染回答（StreamingText 组件），`done` 后展示引用与耗时；`aria-busy`、输入与按钮禁用、可取消；
  - `done.degraded=true` 时显示"知识库暂不可用，本次为直接回答"警示条；
  - 示例问题 chips：来自 questions.csv 精选（如"读书会什么时候举行？"）。
- **清空对话**（F10）：会话菜单内"清空本轮"，二次确认，成功后保留会话仅清消息。

### 3.2 知识库页 /knowledge（F01/F02/F03 + 拓展B）

- **资料管理**：文档列表（标题、标签、版本、状态徽标：启用/停用/待重建），上传 .md、启停用、删除（均带确认）；删除/停用后触发 F3 状态提示；
- **建库面板**：chunk_size（50-1000，默认 500）、overlap（默认 75，校验 `0 ≤ overlap < size` 前端先挡）；"重新建库"按钮 → 进度条轮询 `GET /api/index/tasks/{id}`（阶段/百分比/片段数）→ 完成显示"文档 N 份，片段 M 条"；
- **状态提示**（F03）：顶栏系统状态灯 + 页内横幅，三种态：
  - 就绪（manifest 与配置一致）；
  - 待重建（改了参数/资料变动/AI 服务标记不一致）→ 全站可提问但提示结果基于旧库；
  - 不可用（AI 服务降级）→ 建库与提问禁用，仅 direct 模式可用；
- **片段浏览**（拓展B，+5分）：按文档分组 + heading_path 树 + 关键词过滤（如搜"续借"）；相邻片段并排展示可看到 overlap 重叠；片段卡显示 start/end 与来源路径。

### 3.3 评测页 /eval（F09）

- 发起批量对照测试：选择问题集（T01-T10）、模式（rag/direct/both）、k → 调 `POST /api/eval/batch` → 进度展示 → 结果表（问题/回答/命中关键词/来源/耗时）；
- 结果导出 CSV；历史评测 run 列表与对比（v1 vs v2 参数效果对比就靠它）。

## 4. 与后端的对接

- 基地址 `/api/v1`，走 Java 网关（vite dev 用 proxy 转发）；**前端永远不知道 /internal 的存在**；对话一律走 `POST /api/v1/chat/stream`（SSE 事件协议见规格 §7.5）；
- 工程结构采用规格 §4 的 **feature-first** 组织：`features/chat`（MessageList/ChatInput/StreamingText/SourceRef/RetrievalTrace）、`features/knowledge`、`features/eval`、`features/auth`；组件禁止直接用 axios，统一走 `api/` 抽象层；服务端数据不进 Pinia；
- 轮询规范：建库进度 1s 间隔轮询 `/api/v1/index/tasks/{id}`，任务终态停止；
- 错误处理：`409` 待重建类业务提示用横幅；`503+degraded` 走警示条不打断对话；网络错误统一 toast + 重试按钮；
- 类型定义：按后端 API 文档生成 TS 接口（openapi-typescript），`Citation / RetrievalTrace / IndexStatus` 为核心模型。

## 5. 交互与质量要求（承接原验收标准）

- 可访问性沿用 v1 要求：aria-busy、按钮禁用态、气泡 role=log；
- 来源可核对是硬验收：每个引用徽标必须能打开含原文摘录的引用卡；
- 改参数未建库 → F3 待重建提示必须出现（跨页面持久）；
- 响应式：≥1280 三栏完整，窄屏会话列表收起为抽屉；
- 主题：延续现有浅色主题，支持后续暗色（CSS 变量预留）。
