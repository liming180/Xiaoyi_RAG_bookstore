## 交付修订（2026-11-03）

1. **身份边界**：认证 service 校验真实密码哈希，controller 不直连用户仓储；删除 dev-token、任意用户名冒领及用户 1 兜底。演示认证仅显式 demo profile。签名 token 验签、验证过期/发行者；缺身份 HTTP 401/code=40100，缺内部密钥启动失败。使用 INTERNAL_TOKEN，不保留默认密钥。
2. **资源边界**：文档以 uploadedBy 为所有者；会话沿用 userId。列表、按 ID 读写、内容哈希去重、片段、任务、状态与评测均带当前身份。非所有者文档按现有契约 40401，避免泄露存在性。所有者来自服务端认证，不接受前端指定归属。接口隔离未覆盖 Python 召回之前，不宣称完成多用户隔离。
3. **索引边界**：内部契约先定义用户范围、提交幂等键与 generation，再同步 Java/Python/mock；按用户构建与发布，批量标脏和清旧代必须限定用户。建库只提升本次实际包含且版本未变的资料；新上传资料保持待建。
4. **事务边界**：原子占位创建任务，事务外远程提交，再短事务回写；提交超时重试沿用幂等键。键包含用户、资料版本快照、参数、模型，不以参数永久唯一。新 generation 校验后原子切换，失败保留旧代。
5. **SSE 边界**：持久化成功后只发一次携带数据库真实 messageId 的 done；数据库失败、线程池拒绝必须 error 并结束，禁止伪造成功。客户端断开取消上游并释放连接。模型故障降级与持久化失败分开处理。
6. **测试与实施**：安全改动同批补回归并迁移登录 fixture；先锁公共行为再拆 Chat/Index 服务，不用私有函数测试代替状态机测试。CI 启动独立测试库和服务、注入密钥，运行 Java/Python 单测、MockMvc、根黑盒、契约检查。不清空开发库，不改历史 Flyway 校验和，不自动提交或打 tag。

设计采用现有 Spring Data JPA 与 MVC/SseEmitter，不为修复迁移 ORM/HTTP 栈。Redis/Celery、K8s、完整遥测暂缓；Python 执行状态的持久化和恢复不可因此延期。Java 仍拥有业务库，Python 只持有独立执行状态和索引产物。具体任务范围、验收和回滚以施工单 H0–H4 为准。
> 定位：重构后的 **Java 业务后端**设计——业务能力 + 统一 API 网关，AI 能力全部委托 Python 服务。

## 1. 为什么用 Java 做业务层（可行性结论）

**Java（业务）+ Python（AI）双栈方案可行，且是业界主流模式**：

- RAG 管线（切分/嵌入/检索/重排/编排）强依赖 Python 生态，这部分**留在 Python**，不强行移植；
- 用户体系、资料管理、会话记录、任务编排、审计日志这类业务能力，Java 工程化能力（事务、权限、并发、监控）更成熟，**用 Java 承担**；
- 边界清晰：**Java 拥有所有业务数据与状态，Python 无状态只做计算**。数据库只有 Java 访问，Python 不直连业务库；
- 代价：两套服务部署与运维、跨服务联调链路变长——通过明确的 API 契约 + docker-compose 一键启动来抵消。

## 2. 技术栈

| 项 | 选型 | 说明 |
|---|---|---|
| 语言/框架 | Java 17（或 21 LTS）+ Spring Boot 3.x | Web MVC 起步，够用 |
| ORM | MyBatis-Plus（或 Spring Data JPA） | 团队熟悉度优先 |
| 数据库 | MySQL 8 | 业务数据唯一数据源 |
| 文档存储 | 本地磁盘卷 + `Storage` 接口抽象 | 原始 md 文件；MinIO 列 P5 可选，接口留好即插即换 |
| 缓存 | Redis（P5 可选） | 语义缓存/会话热点时再引入 |
| 服务间调用 | Spring WebClient + Resilience4j（熔断/重试/降级） | 调 Python `/internal/v1/**`；统一超时与降级 |
| 鉴权 | JWT（Spring Security） | 阶段1 可先做单用户/演示模式，但表结构预留 |
| API 文档 | springdoc-openapi（Swagger UI） | 前后端协作依据 |
| 部署 | Docker Compose：前端(nginx) + java-backend + python-ai(+milvus 阶段2) + mysql | 一键起全套；镜像拉不到时用 `tools/local_mysql.py` 直连本机 MySQL，表结构同样由 Flyway V1–V7 建立 |

## 3. 模块设计

```
com.xinghe.bookstore
├── controller      -- 对前端 REST API（见 §5）
├── service
│   ├── ChatService       -- 聊天编排：组装请求 → 调 /ai/chat → 落库消息与引用 → 返回
│   ├── IngestService     -- 建库编排：调 /ai/ingest → 记录任务 → 轮询/回写进度
│   ├── DocumentService   -- 资料管理：上传(md)、版本、启停用、删除
│   ├── SessionService    -- 会话管理：创建、历史消息、清空（F10）
│   └── EvalService       -- 批量对照测试（F09）：调 /ai/eval/batch，结果落库导出
├── client
│   └── AiClient          -- Python 服务封装：超时、重试、熔断降级
├── entity/repository     -- 表实体与 DAO
├── config/security       -- JWT、CORS、服务间 token
└── exception             -- 统一错误码与响应包装
```

### 关键编排逻辑

**聊天（POST /api/v1/chat/stream，SSE 透传）**：
1. 鉴权（阶段1 演示模式放行）→ 取会话最近 N 轮 history（N 默认 5）；
2. 调 Python `/internal/v1/chat/stream`，逐事件透传 status/retrieval/token/done/error 给前端（Resilience4j 熔断保护）；
3. `doOnComplete` 异步落库：回答、引用、检索轨迹、usage、elapsed_ms 全部写 `message` 表；
4. Python 不可用/熔断 → **降级 direct 模式**（无检索直接问 LLM 或返回友好提示），`done.degraded: true`，前端展示"知识库暂不可用"；
5. direct/both 模式对照（F06）由 Python 一次完成，减少往返。

**建库（POST /api/v1/index/rebuild）**：
1. 校验分块参数（0 ≤ overlap < size），不合法直接 400；
2. 创建 `index_task` 记录（状态 PENDING）→ 异步调 `/internal/v1/documents/parse` 拿 task_id；
3. 定时轮询 `/internal/v1/ingest/{task_id}` 回写进度（阶段/百分比/片段数）；
4. 完成：更新 manifest 摘要；文档增删改/参数变更/模型变更 → document 置 `NEEDS_REBUILD`，与 `/internal/v1/index/status` 比对驱动 F3 状态提示。

## 4. 数据库设计

```
user(id, username, password_hash, role, created_at)                    -- 阶段1内置演示账号，JWT 预留
conversation(id, user_id, title, created_at, updated_at)
message(id, conversation_id, role, content, mode, top_k,
        citations_json, retrieval_trace_json, usage_json,
        elapsed_ms, degraded, created_at)                              -- 完整落库，支撑回看/报告
document(id, title, filename, storage_key, sha256, version, tags,
         status, error_msg, uploaded_by, created_at)
-- status: UPLOADING / PARSING / INDEXED / FAILED / NEEDS_REBUILD / DISABLED
index_task(id, status, stage, progress, chunk_size, overlap,
           embedding_model, doc_count, chunk_count, error, created_at, finished_at)
eval_run(id, name, question_count, result_csv, summary_json, created_at)
audit_log(id, user_id, action, target, detail_json, created_at)        -- 关键操作审计
```

> 设计原则：**RAG 中间产物（引用、检索轨迹、token 用量）全部作为消息属性持久化**——这是实验报告、问题回溯（"回答没标编号先看请求"）和后续评估的数据基础。

## 5. 对前端 API（网关层，前端只认这一层）

| 方法 | 路径 | 对应功能 |
|---|---|---|
| POST | `/api/v1/auth/login` | 登录（阶段1 演示账号） |
| GET/POST | `/api/v1/conversations` | 会话列表 / 新建 |
| GET | `/api/v1/conversations/{id}/messages` | 对话历史回放 |
| DELETE | `/api/v1/conversations/{id}/messages` | F10 清空对话 |
| POST | `/api/v1/chat/stream` | F04 问答（SSE；body: conversationId, question, mode, k） |
| GET | `/api/v1/messages/{id}/trace` | F08 检索过程详情 |
| GET | `/api/v1/documents` / POST / PUT / DELETE | 资料管理（上传 md、启停用、删除） |
| GET | `/api/v1/index/status` | F03 建库状态（片段数、manifest 一致性 → 待重建提示） |
| POST | `/api/v1/index/rebuild` | F02 重建（body: chunkSize, overlap） |
| GET | `/api/v1/index/tasks/{id}` | F02 建库进度轮询 |
| GET | `/api/v1/chunks` | 拓展B 片段浏览（支持关键词过滤） |
| POST | `/api/v1/eval/batch` | F09 批量对照测试 |
| GET | `/api/v1/eval/runs` | 评测历史 |
| GET/PUT | `/api/v1/config` | 分块参数、top_k 默认值等配置 |

统一响应包装：`{ code, message, data }`；错误码表：参数校验 400 / 未认证 401 / AI 服务降级 503+`degraded` / 业务冲突 409。

**流式（可选，阶段2）**：`/api/chat/stream` 用 SSE，Java 侧透传 Python 流式输出；阶段1 用"生成中"状态 + 一次性返回即可。

## 6. 与 Python 服务的集成规范

- 契约：以 `docs/api/openapi-internal.yaml` 为源头，路径见规格 §7.4 与 RAG 文档 §6；双方按契约先行（代码生成，禁止手写漂移）；
- 超时：chat 60s / ingest 提交 10s / 状态查询 5s；
- 重试：仅幂等接口（状态查询）自动重试，chat 不自动重试（避免重复扣 token），由前端决定是否重发；
- 降级：见 §2 聊天降级路径；Python 健康检查 `/internal/v1/health` 纳入 Spring Actuator；
- 服务间鉴权：环境变量注入 shared secret（`X-Internal-Token`），不落代码库；
- SSE 透传：Java 使用 WebFlux 流式转发，事件协议见规格 §7.5（status/retrieval/token/done/error 五类）；

## 7. 非功能需求

- **可观测**：所有对 /ai 的调用记录耗时与结果码；`message` 表即对话审计；audit_log 记资料增删与重建；
- **配置**：AI endpoint/model、分块默认参数、超时全部走 `application.yml` + 环境变量，敏感值不入库；
- **测试**：ChatService/IngestService 用 Mock AiClient 单测；契约联调用 Python 侧 mock 模式（provider=mock 沿用）；
- **里程碑**：M1 骨架+建库链路 → M2 聊天链路+降级 → M3 资料管理+评估 → M4 鉴权+审计。
