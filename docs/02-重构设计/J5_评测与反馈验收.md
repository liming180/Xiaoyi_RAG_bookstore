# J5 评测、反馈与参数实验

J5 实现题库与批量评测、反馈候选池、参数实验共 11 条接口。Java 负责业务编排和持久化，AI 调用通过 `AiServiceClient`；当前仍使用 Mock AI，Python 服务与真实检索链路属于后续阶段。

## 数据与执行

- 题库来自 `assets/eval/questions.csv` 与 `keywords.csv`，打包到 Java classpath。对外类型映射为 `single`、`cross`、`out`。
- 批量任务持久化为 PENDING，再异步执行。每题依次调用 direct、rag，历史均为空，不向正式会话写入评测消息。
- 判分遵循前端 `judge()`：`|` 分组全部命中，每组 `/` 候选词命中一个；只修剪候选词两端空白。
- 评测保存进度、逐题结果、统计及 CSV。CSV 带 UTF-8 BOM，列顺序与前端导出一致。
- 每条助手消息保留一条当前反馈，保存 rating、tags、comment；重复提交更新反馈。负反馈最多创建一个候选，保存对应用户问题快照；决策支持 accepted、ignored。
- 实验展开五轴笛卡尔积，跳过 overlap >= chunkSize 的组合。空结果返回 40004；运行中再次创建返回 40902，聊天返回 40901。
- 实验逐组调用评测接口，向 AI 请求传递全部实验参数，按实际回答与引用计算指标。Mock 仅模拟协议事件与确定性答案，指标不代表真实模型效果。
- 服务启动时将遗留 PENDING/RUNNING 任务置为 FAILED，历史成功记录保留。实验结束或失败释放聊天互斥。

## 本地验收

在仓库根目录执行，MySQL 连接使用用户环境变量 `MYSQL_USER`、`MYSQL_PASSWORD`，默认数据库 `xiaoyi_rag`：

```powershell
mvn -f server-java/pom.xml -q spotless:apply
mvn -f server-java/pom.xml -q verify
py -3.12 -X utf8 test/scripts/serve_java.py --detach --profile gate-probe
py -3.12 -X utf8 test/run_all.py J0 J1 J2 J3 J4 J5
py -3.12 -X utf8 test/scripts/check_j5_restart.py
```

`test/run_all.py` 输出本地报告到 `test-artifacts/backend-gate-all.json`。J5 黑盒测试包含题库、全量双模式评测、参数校验、CSV BOM 与列顺序、反馈落库、候选决策、实验组合与互斥。Java 单元测试覆盖反馈边界、实验异常释放互斥和重启恢复。

重启探针会终止 `test-artifacts/java.pid` 标记的测试进程并重启，以验证遗留任务转为 FAILED、已完成评测保持一致；仅在该脚本启动的本地测试实例上运行。普通 pytest 不重启服务。
